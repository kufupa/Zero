### Current path

- Each room needs its own matching preview; the UI snapshots preview-ready pending rooms and calls `bookRoom` sequentially. A refusal or unverified result stops that invocation. Compatible later rooms can name a confirmed earlier room as their parent; the server loads that confirmation before using the add-room path. [Preview and batch](../../../apps/mail/components/quote-workflow/booking-card.tsx#L1307) · [parent selection](../../../apps/mail/components/quote-workflow/booking-card.tsx#L1348) · [server parent check](../../../apps/server-pilot/src/trpc/routes/quote-workflow.ts#L341).
- A successful preview grants one owner-bound, digest-matched use for ten minutes. When work-item and stay IDs are present the preview can be stored on the work item; there is also an in-process fallback. Commit checks duplicates and consumes the grant under the property lock before spawning the create or add-room CLI. A missing, incomplete or failed guest/date search is treated as a duplicate by the default reader. [Grant](../../../apps/server-pilot/src/ai/pane-stay-save.ts#L39) · [stored grant](../../../apps/server-pilot/src/ai/pane-stay-preview-persist.ts#L86) · [locked commit](../../../apps/server-pilot/src/ai/pane-stay-save.ts#L699) · [reader](../../../apps/server-pilot/src/ai/pane-stay-lookup.ts#L587).

Unmount sets its running reference false, so no subsequent iteration should start; the already-issued request might still have reached HMS and needs its own result checked. When IDs are present, the route attempts to store a returned per-room confirmation or unknown outcome in the work item. It does not persist a whole approved batch. ### Recovery gaps to verify

1. **Later click after uncertainty:** A returned unconfirmed result, unverified result, or caught request error stops the current loop. On a later click, the batch and button filter exclude the uncertain room but do not block the other pending rooms. If another room retains a valid preview, the source therefore appears to permit another commit, subject to the server's usual guard and duplicate checks. This is an inference; no multi-room test of the second click was found or run. [Outcome handling](../../../apps/mail/components/quote-workflow/booking-card.tsx#L1386) · [batch filter](../../../apps/mail/components/quote-workflow/booking-card.tsx#L1317) · [button filter](../../../apps/mail/components/quote-workflow/booking-card.tsx#L1901).
2. **Unknown stored receipt:** The stay guard returns `read_hms` for an unknown outcome without a confirmation, but `commitStay` branches only on `refuse` and proceeds to the normal locked guest/date duplicate read. A confirmation-bearing receipt is refused. The extra duplicate read is a protection; this trace does not establish whether a fresh preview and particular read result can cause an unsafe retry. [Guard](../../../apps/server-pilot/src/ai/work-items.ts#L229) · [route](../../../apps/server-pilot/src/trpc/routes/quote-workflow.ts#L352) · [reader](../../../apps/server-pilot/src/ai/pane-stay-lookup.ts#L597).
3. **Receipt failure or thrown commit:** `workItemId` and `stayId` are optional. With IDs, the route logs a thrown receipt-write error and still returns the HMS result; it also does not inspect `recordStayCommit`'s `not_found`/`already_booked` return. If `runPaneStay` throws, its route's later receipt write is not reached; the pane catches the error and marks that room for checking locally. A reload may therefore lack that receipt. The consumed preview and normal duplicate read remain additional protections. [Inputs](../../../apps/server-pilot/src/trpc/routes/quote-workflow.ts#L105) · [route](../../../apps/server-pilot/src/trpc/routes/quote-workflow.ts#L363) · [receipt return](../../../apps/server-pilot/src/ai/work-items.ts#L1938) · [spawn rethrow](../../../apps/server-pilot/src/ai/pane-stay-save.ts#L759).
4. **Partial and unverified presentation:** Successfully recorded earlier rooms remain represented when a later room fails. However, the batch summary counts any `booked` room with a confirmation without excluding `unverified`, while that room's own card says `Check HMS`. The optional HITL tool classifier also labels a confirmation-bearing result `booked`, including `committed_unverified`. These are source observations, not verified runtime incidents.
