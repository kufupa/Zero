## 5. How classification actually worked

- [Method](/home/ubuntu/projects/zero/docs/research/halloween/corpus-analysis/METHOD.md:5): frame + dedupe → clean HTML/credentials, separate current/quoted text → MIME inventory → extract bounded selected PDF/XLSX text → discover candidate replies (headers/thread/recipient/time, incl reverse search) → LLM labels → targeted attachment/group/reply reviews → action details → aggregate.
- Model didn't discover an open-ended taxonomy: prompt defined fixed overlapping actions `quote`, `booking`, `amendment`, `cancellation`, `payment_proof`, `voucher`, `invoice`, `payment_request`, `group`, `other`; model told to include all applicable. 1 prepared inbound/call; `gpt-6-luna` **medium**, Azure route; strict JSON schema; `store:false`; no model tools. `candidate_replies` are fallible candidate links, sometimes later than request.
- Input packet: `{case, inbound:{date,from,subject,message,quoted_context,attachment_context?,to?,cc?}, candidate_replies:[{reply_id,same_thread,minutes_after_inbound,from,to,subject,body,confirmation_pdf_filename,direct_header_match,...}]}`. Attachment context = inventory metadata and sometimes bounded extraction, **not raw attachment binaries**. Typical caps ≈4,000 current / 2,000 earlier chars in study; later enrichments vary.
- [v22 prompt](/home/ubuntu/projects/zero/docs/research/halloween/corpus-analysis/2026-11-02-centurion-opportunity-prompt-v22-combined-review.md:15): classify current actionable reservation work / `can_help`; actions overlapping. `voucher` = sender supplies relevant accommodation booking voucher for filing; may infer filing without explicit “please file.” Request hotel issue voucher or promise to send later ≠ supplied voucher. Complete MIME inventory confirming no attachment overrides sender's contradictory “attached” claim. Filename + relevant body can support inference, not inspected-content assertion.
- [Classifier schema/runner](/home/ubuntu/projects/zero/docs/research/halloween/corpus-analysis/luna-corpus-runner.py:101): `{results:[{case,reservation_email,can_help,actions,reply_ids,response_type,invoice_handling,evidence_source,evidence,reason}]}`. Evidence/reason = short explanation, not full reasoning transcript. Main run used initial v17/v18/v22, v23 envelope, v24 semantic/reply, document reviews + source-bound v30 corrections; **not one v22 call for every row**.
- [Action-details v7](/home/ubuntu/projects/zero/docs/research/halloween/corpus-analysis/2026-11-02-luna-action-details-prompt-v7.md:3) = later separate pass, receives final classification + packet, instructed **do not reclassify**. `request_actions[]` contains action, state (`requested`/`supplied_for_action`/`promised_only`/`completed_or_confirmed`/`unclear`), scope, task, `nava_supported`, confidence, literal `evidence_quote`; `nava_hypothetical[]` = proposed steps; `observed_replies[]` = observed response / same-request relation. `file_voucher` ≠ `issue_voucher`. File metadata ≠ inspected content. [Details schema](/home/ubuntu/projects/zero/docs/research/halloween/corpus-analysis/luna-action-details.py:82).
