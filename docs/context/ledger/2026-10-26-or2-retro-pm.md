## 7. How to be 10× faster next time

Baseline: the whole or2 run (T1+T2, ~50 units) took **915 min** from prep to the last deploy ([L5](../../research/2026-10-26-or2-retro-pm/L5-10x.md)). Wall clock = (critical-chain links × minutes per link) + prep + tail. or2: 11 links × 50 min (morning) and 2-link chains × ~90 min (afternoon). 10× = ~90 min, which needs **≤2 links × ≤35 min + ≤20 min prep/tail**. Levers, measured where marked:

| # | Lever | Cuts | Saves (est.) | Build effort |
|---|---|---|---|---|
| 1 | **Contract-first T0.** One ≤30-line PR per hub adds the types/API signatures + stub (e.g. `revisionCursor()`, `resetSection()` returning a typed not-implemented). Every unit codes against the stub in parallel; server and UI no longer chain. WIRE would have started at 11:42 against J1's interface instead of waiting until 14:18 | links 11 → ~2 | −390 min (model upper bound) | per run ~30 min |
| 2 | **Area lanes, warm.** One lane owns server+UI of a feature (J1+WIRE) and ships stacked PRs; it knows both sides, so cross-PR P1s (#14, #39, #48) don't happen | cross-PR P1s; cold starts | inside lever 1 | `dispatch.sh` ~30 LOC |
| 3 | **Contract-risk checklist in the brief** for state/history, concurrent edits & stale responses, filesystem retention/races, preview/grant lifecycle, HMS outage paths. The lane writes the race matrix + tests *before* the first push; UI holds a whole section with one wrapper, never per field | 11 adjacent P1s; ~11 rounds | −95–190 min | 20 min (skill + brief template) |
| 4 | **`gate.sh` + `baseline.json`** written nightly from clean main; lanes compare failing sets themselves and never wait for the coordinator | ~297 blocked lane-min; 4 manual clean-main checks | −60–100 min wall | ~60 min |
| 5 | **Green main before the clock** (nightly green-main lane) | 187-min green-main detour | −60 min, more if main is red | standing lane |
| 6 | **`eta.sh`** = longest `needs` chain × measured p50 per unit kind (simple ~40, contract-heavy ~90) + one P1 round + deploy + canary; re-runs on every units.tsv change | ETA misses, owner trust | 0 wall; credibility | ~30 min |
| 7 | **Split at planning, not at the cap**: any unit forecast >400 product lines or touching 2 contract kinds gets split before coding | #607 544 lines, 5 rounds | ~1 round per big unit | in the skill |

Combined, honestly: levers 1–5 take the 915-min run to roughly **300–400 min (2.5–3×)** on today's evidence. **10× also requires the per-link time to halve** (90 → ~35 min), which only happens if lever 3 removes most rework rounds and lever 4 removes the blocked waits. Treat 10× as the target for a run whose units are planned contract-first from the start, not a retrofit.
