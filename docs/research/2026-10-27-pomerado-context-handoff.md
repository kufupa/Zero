## Candidate design and discrimination

A small custom host handoff would run Nava's login on Pomerado's own page after initial navigation, keep credentials in a trusted private path, and handle reauthentication at actual reset/fresh-run boundaries. A host dispatch fence would stop subsequent live browser actions after the requested observation while allowing offline authoring and packaging. These are proposed changes, not existing supported switches and not proven on HMS. The fence must cover all relevant browser/test paths, and finalization may still be blocked if the vendor requires another live example.

Success has separate milestones: authenticated correct hotel; screen read and exploration stopped; native tool actually published; privately reviewed tool run once in a fresh authenticated context; cleanup. If stopping prevents a published artifact, fresh tool replay is blocked rather than satisfied by rerunning a handwritten script. Read-only intent and Guardian are not a hard write sandbox; source review remains necessary before replay. Original screenshot and three-case proof remain separate.
