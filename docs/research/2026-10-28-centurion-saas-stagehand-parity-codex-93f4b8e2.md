## Recommendation

Keep Nava's existing pane, background jobs, human approval and per-property browser lock. Run a narrowly scoped, self-hosted Stagehand experiment against the same HRCEN Labtest record and compare the overlapping read with current Playwright. The profile count is an additional capability, not evidence of full booking or Add-On parity. If the new tool earns its place, integrate it behind existing runner/result contracts; an application rewrite or Codex-driven production workflow is not needed to run the experiment.

Stagehand local supports recorded-action replay and selector self-healing according to its [v4 docs](https://docs.stagehand.dev/v4/basics/act), but provider integration and healing against Infor are unproven in this stack. The [v4 model docs](https://docs.stagehand.dev/v4/configuration/models) describe an Azure custom model callback; a read-only inspection of the installed 4.1.0 `dist/index.d.mts` confirmed it exports the local `ClientLLM` callback and `selfHeal` option. A working Azure adapter and the requested model route have not been exercised. Self-healing a selector does not prove the chosen business record or data is correct. Existing deterministic runners normally make no model inference call; compare real build time, runtime, failures, model usage and verified outputs instead of assuming Stagehand is cheaper.

**Version wrinkle:** the installed 4.1.0 runtime sets an OTLP trace endpoint by default (`https://example.com/v1/traces`) and constructs a trace exporter. We did not inspect the actual payload or observe a send. Its public `telemetry.traces.endpoint` can target a loopback discard sink, although there is no boolean off switch and exporting remains active. For a live-data trial, use an isolated newer version with telemetry unconfigured or otherwise prove the endpoint is local/disabled. The upstream [4.2.0 changelog](https://github.com/browserbase/stagehand/blob/main/CHANGELOG.md) says telemetry is disabled unless explicitly configured. At 18:59Z the npm registry reported 4.3.0 as latest; its published extension source makes telemetry optional and returns without creating an exporter when it is absent. This is a static check, not a live network audit. The 4.1.0 runtime defaults `selfHeal` to false, so enable it explicitly when testing recorded-action repair. Do not change Nava's deployed dependency merely to run the spike.

The user permits the Azure Foundry route as ZDR and accepts a fresh browser/login as an MVP fallback. Retrieve the already-configured credential from the private secret source and fill login fields directly; do not put passwords in prompts or logs. A locally run browser with Azure inference is not locally hosted model inference. Exact Azure deployment and retention settings were not independently verified here.

HRCEN historically had two advisory-lock keys across worker/pane and staff-quote paths. Check the actual active configuration and guard the relevant keys for a live run; do not assume one process-local mutex excludes other sessions. Stop the trial if ownership is lost. [Lock analysis](2026-10-27-hrcen-two-locks.md).
