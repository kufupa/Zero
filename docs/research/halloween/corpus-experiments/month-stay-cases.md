# Booking and amendment cases: 28 Sep–18 Oct 2026

**Status:** Bounded, purposive source review. These are booking and existing-stay cases, separate from the request-first quote study. The cases refine Create/Amend safeguards; they do not change the owner-set Quote → Create → Amend order or authorize writes.

## Finding

The saved snapshot contains the older period; the records are not absent. After filtering each logical message on its own stored timestamp, `active_transport` membership and the Centurion transport, the window contains **3,941 saved logical messages across 2,674 threads**. The selected outbound confirmation-PDF inventory has **381 in-window records**, all marked available. These are saved-source counts, not a complete mailbox or attachment inventory, proof of delivery, or a representative sample. The stored timestamp timezone is unverified.

The added cases reinforce three decisions:

1. **Pre-stay self-mail is an existing stay, never a create request.** There are 47 stored message rows across 12 threads matching the stored pre-stay subject, a confirmation-number marker and sender-to-recipient address equality; 46 rows are marked inbound and one outbound. These counts describe a saved-source pattern only. One selected inbound case independently matched an earlier confirmation PDF and a later saved reader result.
2. **One email can concern multiple already-confirmed stays.** One inbound message refers to four distinct confirmation identifiers; each resolves to an earlier selected PDF sent to the same requester address. Keep the reservations separate. The per-guest allocation and the changes requested for each stay remain unknown.
3. **A later document or HMS read must not replace the decision-time request.** One candidate change journey has two same-identifier PDFs with different arrival and departure values in native text. The later Record View arrival matches neither version, while its departure matches a document value. The email-to-revised-PDF link is a candidate, not proven by a direct reply header; the reason and timing of the HMS difference are unknown.

The snapshot's owner-only source note documents the wider inventory and its limits: [month source inventory](month-source-inventory.md). The 1a/1b/1c boundary is documented separately: [reader capabilities](month-reader-capabilities.md).

## Engineering lens for the reviewed cases

| Reader | What its saved output can help read, when visibly rendered | What remains outside the evidence |
|---|---|---|
| **1a — confirmation** | Search an exact confirmation and return a selected card and its visible grids. Useful for locating each of the four existing stays in MS02 or the stay referenced by MS01/MS03. | Does not establish a new quote, availability, eligible pricing, cross-thread causality, or which of several records a staff member intended. Ambiguity must fail closed, not be guessed. |
| **1b — Record View** | Read visible current fields and grids, including stay dates, room/occupancy, rate and meal facts, organization/agency, status and notes when those fields are rendered. Useful for comparing a requested change and letter version with a later current record. | The saved capture is later than the email and PDFs; it is not historical state. | **1c — Guest Details** | Read visible guest and arrival/departure fields for a selected record. | The saved inventory did not select the guest row. Complete guest lists, attachment-only details, transfer fulfillment and hidden/unloaded data are unknown. The reader output does not prove a write path. |

All 381 in-window selected PDF attachment IDs joined to successful results in the existing later saved capture; they map to 294 unique reader results, each with 1a, 1b and 1c sections. This is an exact **attachment-ID** join to saved read observations, not an email-to-booking truth label. It does not establish availability of the from-scratch quote tools, production readiness, historical state or writable status. **No reviewed reader result proves any field can be written.** Any create/amend action remains a separate human-approved workflow.

## Method and limits

- Filtered mail by each logical message's own stored timestamp from 28 Sep through 18 Oct inclusive; retained source rows individually. Filtered confirmation PDFs by their parent's stored `sentAt` in the same window. No timezone normalization was assumed.
- Used only the supplied saved snapshot, selected original PDFs for the five cases, and existing saved HMS reader results joined to in-window PDFs by exact attachment ID. The PDF inventory is filename-selected, not a complete attachment/MIME export. An absent selected PDF is not evidence that a message lacked an attachment.
- Checked stored participants and available saved message identifiers. Raw MIME was unavailable for the source mail, so complete original email-header chains cannot be reconstructed. Only the MS04 PDF-parent `In-Reply-To` to saved `Message-ID` equality is treated as an exact header link. Other cross-thread links remain candidates or unknowns.
- Native PDF text was extracted locally for selected originals; no visual page transcription was performed. Image-only or otherwise unrendered content may be missing. The 1a/1b/1c observations are from the existing 29 Oct saved capture and are later than the target mail/documents; they are not a historical audit trail.
- Selection was purposive to cover pre-stay self-mail, multiple existing reservations, an amendment/document discrepancy, a header-linked booking candidate and an unresolved association. Five cases do not estimate prevalence, recall or accuracy.
- **Scope audit:** an early exploratory discovery pass briefly surfaced an out-of-window 16 Sep source row during a header lookup, and a broad token scan was started over the full saved corpus then stopped before producing results. Those out-of-window records are excluded from the five cases and all findings here. No out-of-window PDF contents are used. The final private case packet verifies that every selected mail and PDF parent date is within 28 Sep–18 Oct.
- No live system, external service, database, HMS write, outbound email, deployment or product code was used or changed.
