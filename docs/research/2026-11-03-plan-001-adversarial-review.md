### 2.2 The Shared Test Runner + Micro-PR Death Spiral (Explained Clearly)

The owner asked why "one shared test runner" limited parallelism and caused multi-hour delays:

1. **How `/home/orca/bin/remote-vitest.sh` and `/home/orca/bin/remote-typecheck.sh` work:**
   - Both scripts run on a single EC2 instance (`i-008f737974a9ba9b3`) inside **one shared git checkout** (`/home/ubuntu/typecheck/zero`) serialized by **one kernel mutex** (`flock -w 1500 /home/ubuntu/typecheck/.lock`, [`remote-typecheck.sh:160-161`](file:///home/orca/bin/remote-typecheck.sh#L160-L161), [`remote-vitest.sh:22-23`](file:///home/orca/bin/remote-vitest.sh#L22-L23)).
   - The mutex is mandatory for that directory because each job runs `git checkout -q -f --detach "$HEAD_SHA"` and `git clean -ffdxq -e node_modules` ([`remote-typecheck.sh:190-191`](file:///home/orca/bin/remote-typecheck.sh#L190-L191)). Without `flock`, two concurrent jobs overwrite each other's working tree mid-test.
   - **The hidden multiplier:** [`remote-vitest.sh:14-18`](file:///home/orca/bin/remote-vitest.sh#L14-L18) **runs `remote-typecheck.sh` first on every call** unless `SKIP_TYPECHECK=1` is set! And `remote-typecheck.sh:191,210` deletes `*.tsbuildinfo` and runs `tsc --noEmit --incremental false` plus `pnpm install` + `react-router typegen` + `paraglide-js` + `wrangler types`. Thus a single `remote-vitest.sh` call makes **3 sequential AWS SSM round-trips** and holds the single EC2 lock twice for **90–230 seconds**.
2. **How 70 Micro-PRs Turned a 2-Minute Lock Into a 6-Hour Queue:**
   - [`scripts/orch/merge-gate.sh:9,58`](file:///home/ubuntu/projects/zero/scripts/orch/merge-gate.sh#L9) allows up to **500 product lines per PR**.

Rebasing created a new `$sha`, which invalidated `/tmp/or2/gates/$pr-$sha.ok` (`merge-gate.sh:61`) and forced a brand-new ~15m Greptile Apex + EC2 `flock` cycle!
