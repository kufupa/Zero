# Nava pane: one shared staff design

**Decision:** One compact, source-bound form for Quote, Create, Amend, Cancel and Filing; one primary action at each stage. Inspecting `origin/main` `9d388ab` supports the component map below; live HMS behaviour remains unverified in this read-only task.
**Inputs:** [owner plan](/home/ubuntu/projects/zero/docs/plans/2026-11-04-002-feat-nava-pane-prefill-rate-parity-plan.md) and [existing research](/home/ubuntu/projects/zero/docs/research/2026-11-04-nava-pane-prefill-rates-research.md).

## 1. Staff see

Use existing white `Section`, 32px `Field` and full-width `PrimaryButton`; no dashboard or new framework. Example, Amend:
```text
Nava · Amend
From · Subject · Received                         View email
Booking 123456-1 · Guest · Reserved              Change
Departure 18 Nov  →  [19 Nov]                    From email
Room [Standard Twin ▾]   Adults [2]   Children [0]
Rate [CODE | HMS description ▾]
ZAR … / night · … rooms left · Total ZAR …       Nightly details
More fields
[ Review change ]
```
Selected email means the exact inbound message; if several requests exist, select one without discarding the others. Booking/PDF choices show their identity, never a guessed match. Current HMS values stay read-only; requested values beside them are editable.
Required, missing and requested fields stay open. **More fields** holds unchanged supported contact/booker fields and optional details; expose genuine HMS context as read-only and say “Not shown” when unavailable. Labels: “From email”, “HMS”, “You changed”, “Suggested”; explain a suggestion only from actual evidence.
At 320–420px use one column, wrapping option text, no horizontal scroll. Combobox arrows navigate, Enter selects/checks, Escape closes and restores focus, Tab moves normally; announce status/errors, label fields and preserve visible focus. No sticky control may cover fields or the keyboard.

## 2. Exact prominent order and actions

**Quote:** email → guest if known, agency, company → arrival, departure, nights → each stay/room count, type, adults, children and each age, board → rate picker, price/availability/total, requested extras → **Review quote → Make quote** → unsent reply, PDF and Excel. Existing multiple stays/options remain; only show an alternative room if staff selects it; unavailable request gets a one-line decline.
**Create:** email → select existing guest profile → arrival, departure, nights → rooms, up to 8 per supported batch, each room’s guest profile if different, type, adults/children/ages → native agency and company → each room’s rate and actual price/availability → source of business, Track, guarantee, reservation note → HMS confirmation send, message/template and recipient → **Review booking → Go**. Send defaults on for a real guest, only with a valid recipient; Labtest is forced off. No profile match: “Create the guest profile in HMS, then select it here.”
**Amend:** email → exact confirmation, guest, status and booked dates → request → current → proposed arrival/departure/nights, room, adults/children/ages, rate → keep/reprice choice when needed, current price/total → HMS confirmation send, message/template and recipient → **Review change → Go**. Preserve the current rate unless requested or edited. Requested first/last name, guest email and booker name/contact rise into view; other supported edits live in More fields.
**Cancel:** email → exact booking, guest, status and dates → **Review cancellation** loads actual HMS reason choices, guarantee/deposit/policy and penalty if supplied → required reason and optional note → **Go · Cancel booking**. If HMS then asks a fee, show its actual amount/prompt and a separate **Go · Approve charge**; cancellation may already have occurred, so show “Check booking status in HMS.” No invented decline action.
**Filing:** email → choose exact PDF filename (explicit choice if multiple; mark unreadable) → search confirmation plus booked arrival, or surname plus arrival → choose exact guest/confirmation/dates/status → **Review filing → Go · File PDF**. Show “Document listed in HMS” only after fresh document-list readback; that confirms metadata, not PDF bytes.
Create/Amend review displays every submitted business field, selected target, native price and confirmation decision. Sequential multi-room Create shows each room’s result and stops on uncertainty; keep other asks independently actionable.

## 3. Rate, errors and action state

One searchable two-line option: `CODE | native name`, then `currency amount/night · rooms left · board · reason` when actually observed. Selected summary shows total and a collapsed nightly breakdown; collapsed comparison is for multiple rooms/boards. Explicit email request ranks first, then verified agency/company-specific history, then labelled general usage; history never proves a contract or present availability.
Show “Checking…”, “Price not checked”, “Available”, “Not available” with HMS reason if given, “Could not check”, or “Price changed — review again”. Missing from a returned subset means **not checked**, not unavailable. Typed code commits on Enter and triggers one native check, not one per keystroke; `GNC3B`/`GNC4B` are catalogue examples, not proven available.
Beside the rate, **Change quote price** opens existing one-off, saved-rate or formal override controls; formal override requires code, rand/night and who approved/why. It changes the Quote row uniformly per room/night, not HMS. For Create/Amend today show “Changing nightly prices in HMS is not available yet.”
After native setter and saved-night readback proof, **Change nightly price** opens date-by-date `HMS price → [new R price]`, approved-by/why, and old/new total before Review; enable only the nightly edits HMS demonstrably supports.
Create Market Segment is native-derived/read-only; guest opt-in remains false/read-only. Amend can write dates, room, occupancy, rate, guest/booker contact and confirmation; agency, company, source, guarantee and note are read-only context only when actually read. Board is derived from the native rate where no independent setter exists.
Inline errors: “Select the original email”, “Select a guest profile”, “Enter an age for each child”, “Choose a cancellation reason”, “Select a PDF”, “Choose a booking”, “HMS could not check the price”. Link the missing summary to each field; never show internal codes. During a slow check: “Checking HMS. This can take a minute.”
Write state: edit/missing → **Review** (native preview, no Save) → **Go** once → checking → **Verified** only after fresh business-field readback. A changed source, target, PDF, dates, room, occupancy, party, board or price invalidates the dependent observation/review; a final price change returns old/new and requires Review again before Save. Unknown: “HMS may have saved this. Check HMS before trying again”; reconcile the exact target, never blindly retry.
Results: Quote “Quote ready · Reply not sent” after a current price check; Create “Booking verified · [confirmation]” per room; Amend “Changes verified · [confirmation]”; Cancel “Cancelled · [confirmation]” after fresh status read; Filing uses the document-list result above. A Quote never implies a saved booking.
