## What the source actually does

- The native MCP `mint` endpoint starts an integration build, not simply a direct request to read a screen. See [pinned MCP server](https://github.com/Pomerado/pomerado/blob/7349a1c2/typescript/src/standalone/mcp-server.ts#L181-L217). It can involve model authoring, Guardian review, execution, tests and publication review. Stage occurrence and its time are not established for this run merely by reading source.
- The native [job view](https://github.com/Pomerado/pomerado/blob/7349a1c2/typescript/src/standalone/mcp-jobs.ts#L132-L157) exposes running, input and terminal states, not individual activity. The trial's private client records status changes only; it does not expose a live browser transcript. This explains our visibility gap, not the duration itself.
- The actual EC2 compiled CLI passes no `timeoutMs` override through the native invocation. Its compiled `mint-state.js` creates a deadline from that option and `runtime/deadline.js` defaults to 20 minutes active mint time. Time waiting for user input is excluded, and browser/session setup, publication or non-cooperative operations can affect wall-clock duration. It is not an instruction to cancel the trial.
- Pinned source sets a Guardian call timeout/retries and a minter transient-retry budget: [Guardian model](https://github.com/Pomerado/pomerado/blob/7349a1c2/typescript/src/guardian/model.ts#L15-L26), [minter retry](https://github.com/Pomerado/pomerado/blob/7349a1c2/typescript/src/mint/openai.ts#L202-L214). These show possible sources of latency, not proof that a retry or particular Guardian call caused this run's delay.

Static role checks showed Luna max configuration; they did not provide an effective per-call provider/effort receipt.

The actual EC2 compiled `standalone/mint-state.js:88–104` explicitly refuses a live reset in that host-only state with `ScopeDenied`. This is a concrete compatibility risk, including for native reset/live-test paths, but no evidence shows that branch ran or caused this delay. Do not silently patch a running trial or claim it did.
- An independent compiled-file comparison found the native Guardian execution, live-test, publication and request-context modules byte-identical to the pinned vendor EC2 build; the login host, mint-state and fresh-run operation modules differ. An omitted explicit minter effort defaults to max in the compiled minter source. These are static observations, not proof of successful calls.
- The separate Pomerado Cloud attempt ended `website_sign_in_unavailable` after 29m22s, despite an earlier `verified`/`saved` login report and a later fresh run returning to login. Its deeper cloud execution trace was unavailable. This is independent negative evidence for the same HMS target, but does not isolate vendor quality from HMS/session or setup behavior. See [auth diagnosis](2026-10-27-pomerado-auth-diagnosis.md).
- We selected full minting because the approved proof also aimed at a generated tool; it is more work than a one-off screen read. Whether that choice, our bridge, model/provider latency, Guardian, HMS behavior, or some combination caused the long gap is unresolved. A direct read-only browser baseline would answer a different question and is not a replacement for the authorized generated-tool proof.
