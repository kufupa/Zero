1. **Native Add-Ons:** no request key, UI or write/readback path. Define exact Infor Add-On interaction first. Keep meal-plan/rate and shuttle/dinner quote extras separate.
2. **Children:** code already accepts age arrays but deliberately refuses create; straightforward write gate, then current Stay age editor review.
3. **Create correctness:** verify exact company/agency binding; fix required-field check/options; show actual HMS status, not only confirmation number.
4. **Manual intervention remains for rate overrides and unsupported optional fields:** quote override amount/authorised-by, A/R account, billing reference, Profile ID, plus native fields excluded by schema (e.g. title/VIP/settlement). Add only where current property/source proves need; no invented defaults.
