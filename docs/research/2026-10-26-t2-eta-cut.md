**Same 8 units, same coders. The time was in the plan's shape, not the code.** Owner asks 232–233. Plan: [T2 fast re-plan](../plans/2026-10-26-003-t2-fast-replan.md).

## 2. What we kept (why it isn't reckless)
- PRs stay small (≤250 product lines). or2 data: PRs of 150–299 lines needed rework 4/9 times vs 4/19 under 150. In mh1024 a 562-line PR took 4 P1 rounds / 2 h 37.
- Round 3 with a fresh P1 means split or strip, never a 4th round.
- Holds unchanged: no real-guest HMS writes, flags, sends.

## 4. Prompting non-Claude lanes (Grok via Cursor, Luna via Codex)
They have no repo memory, so every prompt is explicit: `run-lane.sh` sends the full brief + `lane-protocol.md` (owned files, exact steps, named test, gate commands, the never-do list, P1-fix loop, PARALLEL MODE rules, baseline exemption). Anything a Claude session "just knows" goes in the protocol file, never assumed.

## 5. Retro lessons ([or2 retro](../context/ledger/2026-10-26-or2-retro.md))
- Every fix that stuck was a script or hook (merge-gate, no-tsc hook); every fix that repeated was a prose rule. So the next fixes are scripts: `gate.sh`, `canary.sh`, `eta.sh`.
- The coordinator (Opus) must not run live canaries itself; a canary lane does. ~$82 → ~$25 Opus.
- Re-quote the ETA whenever units are added (240 min was quoted for 22 units; the run had 30+).

## 6. Rule for every future run
Speed mode by default: maximum parallelism. A dependency is real only if the unit needs another unit's new API or data; a shared file is never a dependency. ETA = longest real chain × measured minutes per unit + one P1 round.
