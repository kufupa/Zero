# 2026-10-25 pane de-duplication review

**Baseline:** `origin/main` / `HEAD` `56b9c16b7`. Static source review for U13 / owner ask 222. No product files changed yet.

## Recommendation

One Stay/rate source should own quote inputs. Keep its room, date, occupancy, request, and selected-rate controls. Remove their repeated summary/edit copies from `BookingCards`; keep the explicit HMS preview/book action and all fields that only exist for creating a reservation. Make the current group values, plus the top contact block, the inputs to create.

This fits within the U13 limit of two implementation PRs: (1) stay/rate ownership and booking-summary removal; (2) top-contact-to-create wiring, if it cannot safely share PR 1. No server schema or HMS option list needs removal. Before removing either room/rate editor, preserve its options and editable fallback in the retained Stay/rates UI.

## Countercase and limits

Removing repeated values can make manual HMS entry harder, and merging two option lists can expose unmatched or duplicate room codes. Mitigate by retaining the Stay/rate source, preserving the union of every current room-type option and the free-text rate-code fallback, and keeping the generated HMS-notes copy action. Do not claim the cross-hotel visual check passed: the existing gstack viewer binary is absent, and its setup requires explicit permission.
