## Model and read-only boundaries

A fresh Stagehand v4 script is preferred; the older guarded runner hard-requires a property guard and is not the starting point for the current owner-directed no-lock trial. The old Azure callback handles structured JSON generations and rejects tools and images. Current [Stagehand v4 documentation](https://docs.stagehand.dev/v4/configuration/models) describes structured generations for `act`, `observe` and `extract`, so the callback may already work for text-only actions; this has not been demonstrated on HRCEN and any change should follow an actual incompatibility. A model-free Stagehand page script is simpler but does not exercise Stagehand AI `act` or `extract`.

[Stagehand v4 does not expose Playwright-style HTTP route interception or response listeners](https://docs.stagehand.dev/v4/migrations/playwright). A standalone Stagehand script therefore has no equivalent of the old Playwright network guard; constraining actions and avoiding Save is not a technical guarantee against every write. The old Playwright guard blocks common mutation routes but is itself not a complete proof. A separate network guard is distinct from a Playwright login or navigation fallback. For the grid, inspect DOM or the in-page store and scroll; do not claim raw response capture through a nonexistent Stagehand listener.
