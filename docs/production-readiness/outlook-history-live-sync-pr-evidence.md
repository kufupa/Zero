## Reviewed recovery corrections

The full local review ran all fourteen applicable perspectives: correctness, testing, maintainability, standards, agent context, prior learnings, security, performance, API contracts, migrations, reliability, adversarial failure cases, frontend races and deployment verification. Each surviving finding received a separate independent validation; the parent execution applied the concrete fixes. Original findings and validators remain in the local review artifacts.

- Heartbeat controls now require the authenticated source as well as the caller-chosen request key. Valid rapid restart contention returns retryable claim-busy and retains the protected checkpoint/spool with reads stopped.
- Same-version inventory stubs can atomically receive full qualified live evidence before artifact declaration; already enriched/declared rows retain replacement guards. Valid full metadata uses the bounded1MiB upload envelope.
- Unchanged reconciliation pages update new memberships without reading or rewriting every earlier scan. A real PostgreSQL trigger/logger regression records zero old-row work over twenty sweeps; actual gap/recovery still repairs all twenty-one scan counters.
- Later explicit staff drafts use the existing authorized current-context contract; automatic triage/shadow retries retain their earlier immutable inputs and pinned artifacts.
- Large sealing keeps only the same still-live owner/fence renewed with COM-free server work. Pause/revocation/expiry/takeover cancels sealing; acceptance still requires fresh authority. Independently authorized retries share current work or verify a persisted accepted receipt through exact immutable HEAD identity without a full rehash.
- Native artifacts are declared and sealed individually, permitting one oversized original without a multi-role quota deadlock. Cleanup requires every accessible staged role sealed. Known pre-floor ready rows skip export. Changed snapshots produce fresh observation evidence and explicit supersession.
- Failed event hints retain their original timestamp and protected references, retry with bounded backoff and request one full recovery per failed generation. Logout followed by new activation starts fresh; late cancelled activation remains fenced.
- Canonical attachment reconciliation matches content/presentation occurrences across independent POP3/native receipts. Duplicate deliveries reuse display rows, two identical attachments in one original remain two, and richer filename/CID/inline variants remain distinct. Independent original receipts remain retained.
- Hosted polling responses and errors are fenced against control changes and source epochs; polling cannot clear a control's busy state or overwrite a completed Pause/Resume.

A history-first old-authored fixture creates no work until that verified receipt and then admits once; repeated UIDLs and existing operational rows never replay.
