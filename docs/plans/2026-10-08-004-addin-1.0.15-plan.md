## 1. Folder report (`POST /api/outlook/native/folders`)

### 1a. Native (add-in)
- Trigger: after successful `REGISTER_NAVIGATION` (`TaskPaneControl.cs:224-235`) and after `PairAsync` (`OutlookBridgeAuthorization.cs:243-259`). Non-fatal: failure logs and the pane shows "Refresh folders". Navigation still proceeds.
- COM, enrolled store only (`ResolveStore(enrolledStoreId)` + `OutlookMailOperationPolicy.EnsureMailInRequestedStore`):
  - `storeId` = `store.StoreID`; must equal `_credential.StoreId`.
  - `rootEntryId` = `store.GetRootFolder().EntryID`.
  - `inbox` / `drafts` / `junk` = `store.GetDefaultFolder(olFolderInbox=6 | olFolderDrafts=16 | olFolderJunk=23)`; each must have `StoreID == storeId`.
  - `storeSmtp` = `Session.Accounts[i].SmtpAddress` where `DeliveryStore.StoreID == storeId` (pattern `OutlookMailOperations.cs:383-394`). Null for delegated/shared stores that are not user accounts.
- Send: `SignedPostAsync("/api/outlook/native/folders", {storeId, storeSmtp, rootEntryId, inbox, drafts, junk})` (`OutlookBridgeAuthorization.cs:270-289`). Well under the 4 KB cap.
- Run COM on the Outlook STA, marshalled through `OutlookBridgeDispatcher` like the existing `LIST_*` actions.

### 1b. Server
- Routes: add `app.post('/api/outlook/native/folders')` in `main.ts` (pattern `:70-76`). In `http/outlook-native.ts` add the path to the allowlist (`:36-37`) and to the signed branch (`:59-69`), which verifies the signature and calls `reportNativeFolders`.
- New `reportNativeFolders(db, verified, body)` in `outlook-security/authorization.ts`, next to `provisionApprovedFolder` (`:49-58`):
  1. Require an unexpired `outlook_navigation` row for the device (`:61-73` semantics). This proves a signed-in pane navigation is active (D9).
  2. `body.storeId === verified.storeId`, else 403. Tokens bounded by `isToken` (`:32`).
  3. Candidate grants = `outlookDeviceGrant` JOIN `mailboxAccess` JOIN `mailboxTransport(isActive)`. Keep those passing `isDeviceAuthorized` (`device.ts:147-161`). None means 403.
  4. If `storeSmtp` is present, skip any transport whose `email` differs (case-insensitive). This never fails the whole report.
  5. Per authorized transport, insert `outlookApprovedFolder` rows: `inbox` (Inbox), `drafts`, `spam` (from junk) with **insert-if-absent**. Do not reuse `provisionApprovedFolder`, which overwrites `kind` (`:55-57`). An operator row with another kind is never changed.
  6. Read root: call `approveReadRoot` (`device.ts:179-215`) once, for one grant (the self-enroll user, else the first), with `rootEntryId` = reported inbox (D2). If it throws "at most one active root", keep the existing root and log.
  7. Audit row (section 2) and `200 {reported:true, approved:{inbox,drafts,spam}}`. Denials return generic 403, as in `http/outlook-native.ts:65,73`.
- Rate limit: at most 30 reports per device per hour (count of audit rows). Otherwise the upsert is idempotent.
- Migration `apps/server-pilot/drizzle/0046_outlook_self_enroll.sql` (latest is `0045`): tables `outlook_device_audit`, `outlook_enroll_intent`; column `outlook_device.store_smtp` (nullable). Drizzle schema in `src/db/schema/outlook-device.ts` and `outlook-authorization.ts`.
- Today's server stopgap (auto-approve observed folders) stays. Insert-if-absent keeps both compatible. Remove the stopgap once 1.0.15 adoption is confirmed.

Default folders as move destinations (D1): the server allows `MOVE_EMAIL` only to kind `triage` or `inbox` (`authorization.ts:165`) and `MOVE_TO_SPAM` only to `spam` (`:166`). Drafts is never a move destination (`:156-157`). Recommended: auto-approve Inbox and Junk only, which matches what the README procedure approves today. Triage stays operator-only (D3).

## 2. Self-enroll ("Connect" click, no code)

### Handshake: how the session binds without leaking
- Today the session never leaves the server. `bridgeTicket` (`apps/server-pilot/src/trpc/routes/workstation.ts:940-967`) → `issueBridgeTicket` checks the cookie session (`authorization.ts:79-93`; legacy profile only, `:80`) and binds the ticket to `sessionId` (`:135-140`). The navigation challenge is created by a device-signed `register-navigation` (`:61-73`). Native holds only an opaque 60 s ticket or challenge.
- Self-enroll uses the same shape. The device does not exist yet, so this bind is unsigned:
  1. Pane: `POST /api/outlook/native/bootstrap` (public, `http/outlook-native.ts:56-58`) yields `paneChallenge` (43 chars).
  2. Pane: new tRPC `workstation.enrollmentIntent` next to `bridgeTicket`. It reads the cookie and header `x-zero-active-transport`, runs liveSession, checks `emailVerified` and `mailbox_access`, then inserts `outlook_enroll_intent(challenge_hash, user_id, session_id, transport_id, expires_at = now+60s, consumed_at)`. Returns nothing secret.
  3. Pane → native: `PAIR_DEVICE {paneChallenge}` (`use-outlook-bridge.ts:923`; deadline `:263` drops from 12 min to 60 s).
  4. Native shows one confirm dialog (below), reads StoreID and storeSmtp, generates deviceId and secret (existing, `OutlookBridgeAuthorization.cs:248-251`), then POSTs unsigned `/api/outlook/native/self-enroll {paneChallenge, deviceId, storeId, storeSmtp, version:"4", secret}`.
  5. Server `selfEnrollDevice` in `device.ts`, beside `enrollDevice` (`:61-87`), in one transaction:
     - Conditional update consumes the intent (pattern `device.ts:70-74`). Must be unexpired and unconsumed.
     - Re-check liveSession for the intent's `session_id` and `user_id` (`authorization.ts:79-93`).
     - Apply the gates below.
     - Insert `outlookDevice` (+`store_smtp`) and `outlookDeviceGrant` (pattern `device.ts:78-81`).
     - Write audit row; return `{enrolled:true}`.
  6. Pane: `refreshPairing` (`use-outlook-bridge.ts:924`), then normal `REGISTER_NAVIGATION`, then the folder report (section 1).
- The session cookie never leaves the server. The secret goes only to the server, as today.

| Gate | Source |
|---|---|
| Live Better Auth session (legacy profile) | `authorization.ts:79-93` |
| `user.emailVerified` | `device.ts:50` |
| `mailbox_access(user, transport)` and `mailboxTransport.isActive` | `device.ts:47-52` |
| `storeSmtp` equals `mailboxTransport.email` (trim, case-insensitive). Missing storeSmtp = deny | new |
| Intent unexpired (60 s), unconsumed, same session | new |
| Rate limit: at most 5 attempts per user per 24 h; at most 1 active device per (user, transport, store) (D5) | new, audit table |
| Audit row per attempt: outcome, userId, transportId, deviceId, storeId hash, IP hash, UA | new |

Residual risk (D4): the POST is unsigned. Anyone holding the one-use 60 s challenge can enroll a device bound to that session's user. Mitigations: 256-bit random challenge, one-use, session-bound, delivered only to the origin-locked pane (`TaskPaneControl.cs:122`, `IsTrustedPaneOrigin`), plus a native click.

## 6. Risks
- **Code signing / SmartScreen**: setup.exe is unsigned, and the VSTO cert changes per run (`outlook-vsto.yml:62-72`). README `:44` warns of SmartScreen. Investigation `nava-outlook-addin:docs/superpowers/plans/2026-10-07-installer-detection-investigation.md` records Defender/IOAV quarantine on the protected download. Mitigation: OV/EV code-signing cert (D7). Staff may face a click-through.
- **Device authority**: the folder report is device-signed, not staff-signed. A compromised native process can approve default folders and a read root in its own store. Bounded by: enrolled store only, live navigation required (1b.1), default folders only, read root = Inbox (D2).
- **Shared/delegated stores**: `Session.Accounts` does not list them, so storeSmtp is null and self-enroll is impossible. Keep operator path.
- **One read root per device store** (`device.ts:207-208`): multi-staff devices get one root.
- **Revoke strands user**: no reconnect path (`OutlookBridgeAuthorization.cs:245,465`).
- **Upgrade identity**: no `AppId` today; credential survival unverified.
- **Unverified**: `UseNewOutlook` value name and type; `Account.SmtpAddress` for shared stores; gitlink drift (`eeb76de1` vs `0f2d0853`).
- **Estimate**: folder report 2-3 days (server 1, native COM 1, VM and CI 0.5-1). Self-enroll +1-2 days. Installer about 1 day plus VM. Release 0.5 day. Total about 5-7 days.
