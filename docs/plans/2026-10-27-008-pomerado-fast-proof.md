# Fast Pomerado proof and Nava fit

Date: 2026-10-27. **Finalized for review; execution paused until the owner says go.** This plan supersedes plan 007's Terra routing and its old forecast, but keeps the original three-case acceptance and ask 304 control decision. It incorporates the [Grok review and adjudication](../research/2026-10-27-pomerado-grok-plan-review.md). No runtime state was checked while finalizing this plan.

## Goal and scope

Have Pomerado mint and publish its own reusable **read-only HRCEN Guest Stay lookup**. It accepts a confirmation number as its only required input. Use the owner's selected screenshot booking as the first private example, then independently compare the generated reader with the three original specified bookings. A successful publication, a complete first-case comparison and a full three-case pass are separate outcomes. If the screenshot booking is not one of the original three, it is an additional case. Determine overlap privately; never assume it.

This is a read-stay trial, not a booking, Add-On, Nava integration, model benchmark or claim that Pomerado is faster than the existing reader. No real-guest write, cancellation, email send, deploy or flag flip is authorized by this planning request.

## Why this is the minimal complete trial

- Reuse the vendor's native flow rather than a public example, custom client or manually coded Pomerado replacement. Keep the controller focused on credentials, job answers, actual errors and results.
- Keep the owner's retained read authority, Guardian, approved private route, existing property lock, source review and cleanup. Do not revive process-wide sandbox proof, outbound proof, expired role proofs, extra credential approval or other discarded prerequisites.
- Vendor runtime comparisons concern pre-minted tools versus computer use. Test a same-booking Nava deterministic baseline before claiming a speed, completeness or cost advantage; it is not a substitute for the requested three-case Pomerado proof.
- For later adoption, integrate behind Nava's existing property-scoped stay-lookup contract and account for the pane's direct job path separately from Mastra. Generic MCP compatibility is documented; Nava-specific integration is not yet proven and is outside this trial.
