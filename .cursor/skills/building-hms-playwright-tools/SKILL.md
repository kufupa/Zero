# Building PMS flows

Build quickly with Codex and Playwright driving the actual PMS. Use the owner’s requested behavior and context; clarify when needed. Give each useful read or action a module with explicit inputs and structured results; compose longer flows on the same page/session where useful. Return options for unresolved identities instead of guessing. Prefer headless Chromium; screenshots still work. Use headed when useful or requested.

New cloud tools are being organized under `apps/server-pilot/tooling/hms-cloud/`; preserve compatible existing imports in `playwright-quote/`. Check which modules are present in the current checkout:

- `centurion-stay360.mjs`: browser, login and Stay 360 lifecycle.
- `stay360-notes.mjs`: automatically closes and privately captures Notes popups; other dialogs stay untouched. The shared browser installs it; install it on any other page setup. Use `takeHandledNotes(page)` to include automatic captures in a reader's output.
- `stay360-confirmation.mjs`, `stay360-record-view.mjs`, `stay360-guest-details.mjs`: composable shallow, record and guest readers. `hms-readers.mjs` exposes them as `readShallow`, `readRecord`, `readGuest` (when present); prior filenames and result keys remain compatible. Shallow accepts optional name/date and returns options for ambiguous matches.
- `stay360-guest-form.mjs`: after `readGuest`, select each loaded guest row and read its detailed form; `readGuestForm` exposes it. `stay360-record-tabs.mjs` verifies the open stay and navigates a record tab; Guest Details, `stay360-documents.mjs` and `stay360-associated-reservations.mjs` use it (when present). Documents and associated reservations are separate readers. `read-*-ui.mjs` runners compose these on one page.
- `stay360-lookup-cli.mjs`: shared JSON input and structured lookup-error output.
- `hms-cloud/lookup.mjs` (when present): live agency, organization and A/R searches and explicit selection on an unsaved Guest Stay. `hms-party-search.mjs` preserves older imports; `booking-lookup-session.mjs` provides a same-session JSONL runner when present.
- `hms-cloud/hms-booking-memory.mjs` (when present): query prior observed party combinations, historical room, rate and guarantee frequencies, and reservation-note / billing-instruction examples by exact address, domain or name, with explicit message role, source-of-business filter and optional evidence. Counts are observed confirmation numbers, not proof of unique stays; rebuild older memory snapshots from source to populate the new hints. Raw notes and observations are private historical evidence, not current policy.
- `hms-cloud/hotel-availability.mjs` (when present): open Hotel Availability, search its group, organization and booking-agency pickers, and read dated inventory and prices for specified room types and rates. Retain the full private snapshot and optionally filter the agent view.
- `hms-cloud/availability-view.mjs` (when present): project a private availability snapshot into bounded room/rate/night observations, with criteria, coverage, inventory and restriction evidence.
- `hms-cloud/availability-display.mjs` (when present): correlate grid text with the response. Visibility is checked within the grid viewport; a parent-page overlay can still obscure an iframe cell, and capture coverage is not exhaustive.
- `hms-cloud/quote-read.mjs` and `quote-view.mjs` (when present): save a full snapshot in a private directory outside Git, then compare nightly room counts with an explicit quantity in a bounded view. An optional exact sum adds verified nightly values only; price and quantity basis, tax and the official total remain unknown. A sufficient count is not proof of rate eligibility or combined availability.
- `hms-cloud/guest-profile.mjs` (when present): search and inspect current guest-profile candidates, then explicitly select a native ID on a blank unsaved stay. A new search invalidates the previous selection token.
- `hms-cloud/guest-stay-form.mjs` (when present): read and edit supported fields, child ages and CMS controls on a guarded unsaved stay. Guarantee selection requires a fake Proof Labtest draft with 2027+ dates; any selected identities must be verified on that page. The fake guest and an A/R account can both be selected. A new search for either entity invalidates its corresponding proof. Pre-populated or unverified profiles and real-guest changes remain unsupported. A checked send box or recipient on a draft is not a sent email.
- `hms-cloud/guest-stay-source-business.mjs` (when present): search, inspect and select the current Source of Business on a blank unsaved stay. One HRCEN probe verified the selected description, while independent native-code readback from the form was unavailable.
- `hms-cloud/guest-stay-room-rate.mjs` (when present): search room-type and Rate Shop catalogs and select a current room type on a blank unsaved stay. Catalog membership is not a current quote. Follow the module's cleanup and uncertain-cancel outcomes when a picker action fails.
- `hms-cloud/guest-stay-rate-plan.mjs` (when present): select or replace a current rate code on a verified blank Guest Stay, then inspect the form changes. The verified fake Proof Labtest profile on 2027+ dates can be combined with a verified A/R selection before the rate; other selected guest profiles remain unsupported. A Rate Shop catalog or rate selection is not a Hotel Availability quote.
- `hms-cloud/labtest-preimage.mjs` and `guest-stay-save.mjs` (when present): establish the current fake-stay census for the chosen dates and permit one narrowly matched save. `labtest-record.mjs`, `guest-stay-amend.mjs` and `guest-stay-cancel.mjs` guard a saved fake record; the amendment currently changes its reservation note only. Independently reopen after a dispatched write. These modules do not authorize real-guest writes.
- `hms-cloud/booking-lookup-session.mjs` and `saved-stay-agent-session.mjs` (when present): compose tools on one page and serialize agent calls. The saved-stay session returns available lookup candidates and supports the guarded Labtest note and cancellation actions; an uncertain action requires a fresh session and reconciliation.
- `create-lab-stay.mjs`, `amend-stay.mjs`, and `write-cli-lease.mjs`: existing write-workflow references; check their actual coverage before reuse.

The Centurion bootstrap resolves Playwright from `tooling/stagehand`, independently of the server package. Fresh worktrees may lack that install: check the bootstrap's pinned version and use an existing matching Stagehand `node_modules` or install it before launching. A missing package or browser is a setup failure, not an HMS result.

Inspect the real UI, build in small stages, and validate the requested behavior in the PMS as directly as practical. For identity lookups, check ambiguous results, blank fields and conflicting hints against real records where available. Skip low-value local test loops; follow the repository's required release checks. Report what was observed and what remains unverified. An observed read field is not proof it is writable.

On Guest Details, the detailed form may remain blank until a guest row is selected. Verify the selected row and matching identity before reading; flag duplicate names when no native ID is available. Loaded rows are not proof that unloaded pages were captured, and detailed forms can contain sensitive identity data. Treat arrival and departure dates as calendar days: converting a local-time date to ISO can shift it by one day.

For dynamic Infor grids, a stale refresh or empty grid is not proof of no matches. Verify the displayed rows belong to the current Run; correlating its response and grid can help. Report errors separately from true zero results and flag capped results so the caller can refine the search. Return native IDs and available distinguishing fields.

For an explicitly empty child-age list on a blank HRCEN Guest Stay, the native spinner was blank and its submitted count was nonnumeric. Establish numeric zero with the native up/down controls and verify the intermediate and final values; keep the request guard intact. A live unsaved draft verified zero → one child → zero.

On a new HRCEN Guest Stay, the Room Type lookup shows a room catalog; the Rate Plan lookup opens Rate Shop, whose grid can return dated room counts and prices together. It also exposes stay-summary, party, promotion and other controls. Proof Labtest probes selected and replaced current rate codes on an unsaved draft, both before and after selecting the verified fake guest, with matching visible and native readbacks. A rate change also changed meal plan, market segment and track; a separate native rate-plan ID was unavailable. These observations do not prove a saved rate or support selecting a rate after a real guest. Hotel Availability is a separate screen and remains the client's quote source; do not treat a rate catalog as evidence of dated availability.

Preserve and report useful loaded fields, labels, search criteria and result coverage; note newly discovered controls and fields even when not yet used. Store raw evidence privately, never credentials in the skill. For broad capped searches, report loaded versus total when known and let the agent refine; paginate when the task needs it rather than dumping the whole catalog by default.

For HRCEN quotes, the hotel directs us to use Hotel Availability because it considers children and produces the correct rate. Its Guests control exposes separate adult and child counts and child-age inputs; a matched live probe showed an age-8 child changed one rate. New Guest Stay has a Hotel Availability toolbar icon that opens an iframe; in one probe the overlay used different dates, occupancy and organization from the draft. Set and verify each required criterion on the availability surface instead of assuming the draft was inherited. Treat other availability screens as separate workflows, not interchangeable quote sources.

On cloud Hotel Availability, room-type and rate-plan filters use checkbox multi-select; the highlighted row is not the checked selection. Blank room and rate filters did not mean all options in a tested Preset search. Verify applied values after Submit. A picker can load only part of its catalog (HRCEN showed 50 of 95 rates); report or retrieve the rest. The results grid can include daily room counts and rates; inspect availability, restrictions and useful response fields without assuming they are all visible in the grid.

For one HRCEN Hotel Availability search, loading all picker entries produced 9 room types and 95 rate plans; HMS returned 496 room/rate rows, not the full Cartesian product. Do not infer that an absent combination is unavailable. The visible picker footer gave the loaded and total counts even when the Ext store's total was zero. Verify the submitted property, dates, adults, child ages, room and rate codes, and party context. The current reader can select agency, organization and group on the availability surface, then verifies the native IDs in the submitted search; selecting a draft field alone does not apply it there. In an adult-only request HMS may omit `childAges` when `childCount` is explicitly zero. Preserve the full private response before filtering a smaller view; the reader does not select a rate or calculate a stay total.

A returned price alone does not prove availability: a live cell had zero rooms with a price, and another priced rate was closed. Preserve room counts and restriction flags, compare counts with a known requested room quantity, and leave missing pairs or unverified combined-room availability unknown. Reject contradictory child counts or room-quantity aliases, including in saved snapshots; do not infer an unknown quantity as one.

The cloud app menu can be technically visible while positioned outside the viewport, and some menu clicks can be dropped during navigation. Verify that the menu and destination actually opened and use bounded retries. When inspecting an unsaved lookup selection, a 200 response alone does not prove success: an HRCEN validation request returned a 200 login page in one probe. Inspect HMS messages and confirm the available native identity and form readback. A failed or incomplete picker read must not be reported as an empty result. Preserve enough known picker state to recover from a failed search, click or close; distinguish a closed UI from an unverified server-side cancel. Return independent copies of inspection results when caller mutations could otherwise alter later selection checks. A temporary route removed on timeout can let a delayed field-change POST reach a weaker context guard. Protect those endpoints for the page lifetime; after an uncertain action, quarantine before awaited readback and use a fresh page so a retry cannot authorize its late request. A request already sent to HMS can still complete. Existing page fences require later routes to use `route.fallback()`, not bypass them with `route.continue()`.

For one guarantee-change request, reading the page from the paused request handler stalled while HMS awaited that request. The successful live approach checked the current fake draft and session immediately before clicking, matched the known native request fields synchronously, and verified the response and form afterward. Keep those request checks and the uncertainty fence; do not broadly permit the endpoint.

For saved Labtest actions, bind the verified identity and a clean full record baseline to the exact native request, and reject unrelated dirty fields. A 200 response is only `awaiting_readback`; reconcile a possible dispatch in a fresh session before any retry. The cloud read-only guard must also block saves indicated by a query-string `pageaction=SAVE`, not only by form fields.

The current HRCEN Labtest save, note-amendment and cancellation guards require agency, organization, group, A/R and guarantee-card links to be blank and verified; a linked or ambiguous field is refused. This deliberately limits the fake-write proof, not the read or unsaved-lookup tools. A full fake lifecycle has been checked through the booking and saved-stay agent sessions with a separate readback after each action.

In HRCEN fake cancellations, HMS can change the status to Cancelled before displaying a possible penalty dialog. Leave the dialog untouched and independently read back status; the warning does not prove a charge, and a zero balance at readback does not prove no later charge. A cancellation is not demonstrated to be fee-free merely because the prompt was not accepted.

Opening a blank cloud Guest Stay also triggered a card-entry POST unrelated to lookup. The shared context guard blocks the observed cloud-vault origin and handler, and a live check verified that normal session behavior; these tools do not support card entry. This observation does not establish coverage for other endpoints or older standalone guards. Never print token-bearing request URLs in diagnostics.

On Associated Reservations, a row can represent the current stay; compare confirmation numbers before treating it as another linked stay. The reported total can be lower than the loaded row count, so do not infer completeness from that total alone.

When an unsaved selection is authorized, choose an explicit ID from current results and read back the selection and dependent fields; the UI may send a server request before Save. Historical PMS choices are evidence, not guaranteed current matches. Keep observed blanks distinct from missing values, and label address roles: an outbound recipient does not establish the inbound sender. Preserve link provenance and conflicts: an attachment match can carry forward an earlier filename or subject inference.

Follow `PRODUCT.md` and current workspace instructions: an agent may read real guests, but writes only to Labtest. Keep credentials and guest values out of logs, comments and this skill.

After a building session, discuss what worked, what failed, and what to change. Update relevant skill copies when a reusable lesson or module materially changes; preserve concurrent work and avoid overgeneralizing from one run.

For historical UI pitfalls, see [references/traps.md](references/traps.md); verify old observations against the current cloud UI and ignore dated model-routing mandates.
