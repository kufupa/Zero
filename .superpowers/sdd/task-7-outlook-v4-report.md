# Task 7 — pane CSP and centrally hosted web release

Status: DONE_WITH_CONCERNS (local implementation verified; real Nginx/EC2/Windows smoke not run).

## Change and deployment order

- The complete publishable client tree identifies a release (`SHA256` over sorted relative paths and file-content hashes, including directory names); `index.html` alone is **not** a release ID. The complete client output is staged under `${WEB_ROOT}/releases/<id>/` without replacing existing files. Symlinks, special files, unexpected client `downloads` trees, and symlinked web-root destinations fail closed. `rsync --ignore-existing`, a checksum dry-run, and a recomputed staged tree ID refuse collisions, missing/extra files, and changing assets. New staged files and public old-tab chunks are root-owned, with no group/other write permissions. No `--delete` touches old releases or `/downloads/NavaOutlookSetup.exe`.
- Only Vite-convention eight-character hashed `/assets/*` filenames **not present in the source `public/assets` directory** are copied append-only into the shared root, with collision verification; public SVG/PNG files stay in each complete immutable release even if their filename looks hashed. If a copied public asset's bytes differ from its source, release staging fails. Both mail and remote-admin first resolve assets in the selected release. Only hashed asset requests may fall back to shared old-tab chunks; stable asset requests never fall back to stale root files. Other root paths resolve in the active release or SPA fallback.
- The helper renders Nginx from the *staged* index and checks its real, regular-file path and complete-tree identity. It hashes every inline `<script>` body (including inline module scripts) as emitted, inserts the hashes into exact `/outlook-pane` `script-src 'self'` without script `unsafe-inline`, rejects weakened `script-src-elem`, and verifies the full tree and candidate against unchanged staged bytes immediately before install. A mismatch aborts without switching the site.
- Exact `/outlook-pane` aliases the versioned *file*, so it does not internally redirect to `/index.html` and lose its location-level CSP. All five headers are explicitly present with `always` there, including on 4xx. The HTTP 301 has the same five security header names (redirect CSP `default-src 'none'`). `/index.html` and SPA fallback on both web-mail and remote-admin select the same immutable release through the same validated Nginx candidate reload; other page/remote-admin CSPs retain their earlier `unsafe-inline` policy. The EXE alias stays unchanged. Old Nginx workers use their old immutable release and matching policy until new workers take over.
- Existing dual-plane validation, ALB target-IP check, Nginx backup/rollback on validation/reload/signal failure, and `--quiesced` (no PM2 mutation/health) remain. Failed candidate validation/reload restores the prior site and enabled link; already-published but unactivated files can remain safely and can be revalidated on retry. No UI-only publish builds or installs a new Windows add-in.
- Chromium found an actual pane CSP violation from the deferred third-party Dub analytics script. The route guard in `apps/mail/app/root.tsx` now skips that script **only** when the current pathname is exactly `/outlook-pane`; other web-mail routes retain their existing analytics behavior. The native pane does not allow third-party JS to fix that violation.
