# Filing

Read [common rules](../references/common.md), [proposal bindings](../references/tools-and-proposal.md), [document rules](references/rules.md) and [reply drafts](references/replies.md).

[Stay action and target rules](../references/stay-action.md) take precedence over the common disposition guidance for this workflow.

1. A genuine existing-stay voucher or proof-of-payment PDF submitted now is Filing, including forwarded billback vouchers and submissions inside invoice or payment follow-ups. Keep Filing when the stay is unresolved or the agency reference is not an HMS confirmation. **Voucher Create vs Filing:** do not guess from "voucher" alone (Thompsons, Nexus, TWF, Cliqit). Cited **6–10 digit HMS confirmation** or confirmation-thread reply → Filing. Explicit new-booking ask ("please book" / "new reservation" / "please reserve" / "kindly confirm") → Create. Else `hms_search_reservations` by surname + arrival: hit → Filing (bind it); confirmed absence (complete search, 0 matches) → Create; unconfirmed absence on a bare voucher/billback submission with no explicit new-booking ask → Filing (unbound target for staff). Staff forwards from Legacy route on the **inner client request**. Distinguish a submitted document from a VCC settlement notice using the already-loaded triage rules. With an explicit submission but no selected PDF, publish `filing/needs_info` with no attachment action; ask staff to select it. Blank body plus a credible voucher or POP PDF is a review draft when the document type or intent is only a hint.
2. Follow the document lookup order per file. **Never** put `"unknown"`, `"TBD"`, PNR codes (e.g. `GVQMVXR`), or agency voucher references into `criteria.reservation_id` / `booking.reservation_id` — only numeric HMS confirmations (`6–10` digits, optional `-1` suffix). When no HMS confirmation is stated, **always** call `hms_search_reservations` with `guest_name` (surname) + `arrival_date` before `proposal_publish`; never skip search and jump to `staff_review` with `reservation_id: null`. Use `propose` for a qualifying submission, whether or not HMS verifies the stay. If submission evidence itself is unclear, use `staff_review` and keep the selected file and document type on the draft. For an unresolved stay leave `reservation_id` and `current_state` null but retain `/actions/0/details/attachment_id` for the first file and the equivalent path for each additional file. Staff checks the actual PDF even when the draft is already bound.
3. Publish one booking and linked action per PDF and intended stay. Use `voucher_submission`, `payment_proof_submission`, or `attach_document` for an explicitly requested other document. In `details`, use the selected `message_id`, exact selected `attachment_id` and a short `description` (up to 200 characters). Give staff editable description and attachment fields; attachment options are PDF IDs and filenames from the selected message only. Cite that message and attachment in evidence. Keep the source message ID fixed. Stop after publishing and any grounded reply draft.
