# Filing rules and native order

- Split voucher/POP submission from requests about invoices, payment links, status or refund. An inquiry alone does not file anything. An agency message can supply a valid voucher; a pro-forma or a promise to pay does not establish payment.
- Use the current selected inbound. Prefer confirmation hints on the selected PDF (`confirmation_hints`, `confirmationNumber` in extracted text, confirmation-letter filename), then subject/thread confirmation tokens, then `hms_search_reservations` by guest+dates from the voucher/POP when the mail is silent. Search PDF-printed supplier, invoice and recipient references as candidates, then use the native confirmation returned for the matching traveller/stay. Bind each voucher or PDF to its own verified stay. Earlier messages may explain context, but a quoted file/reference or sender/time similarity cannot authorize staging. Never choose a different stay to make Prepare succeed.
- Staff checks the actual PDF: voucher/confirmation identity, property, guest, stay dates and any room or charge coverage; proof of payment also needs intended stay, payer/payee, currency, amount and transaction identity when available. If the PDF cannot be read, don't infer its contents from filename or label. Never expose bank or card credentials in draft or reply.
- Staff confirms one exact file on the final revision. The worker fetches bytes for that message and attachment ID only. Do not send raw bytes, object keys, URLs, or handles in the proposal.
- Native order: verify the exact Stay 360 stay and current Documents view, then open **Create/Upload Document** without submitting. The observed code identifies this draft. It does not establish an HMS document category. The form shows document code, description and selected filename.
- Incomplete Documents coverage cannot establish absence or settle duplicate status. Same filename does not prove duplicate. If target, file or form is unavailable, report the specific gap. A Documents list alone is not a successful Prepare.
- No upload, Save, Go, email, payment posting, refund or folio mutation. Receipt, unsaved Prepare, stored filing and cleared funds are separate facts.
