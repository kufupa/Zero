# Amend field rules

- Supported patch keys: `arrival_date`, `departure_date`, `adults`, `child_count`, `room_type`, `rate_plan`, `first_name`, `last_name`, `booker_name`, `booker_contact`, `reservation_note`. Keep unsupported deltas visible for staff rather than inventing fields or propagating a change to other stays or a guest profile.
- Date targets are ISO dates. Preserve every explicitly requested target even when already matched in HMS; flag the no-change result. A request for an earlier arrival changes arrival; a stated checkout is the departure, not an occupied night. Do not derive the patch from a mismatch between an earlier document and current HMS.
- For an explicit room change use `hms_read_catalogue` for `room_type`. Populate a native code only on a unique direct match. Preserve an unresolved room mix or rate description in staff context; rate/board prose is not a `rate_plan` code. An invoice correction alone is not a room rate change.
- Prepare reads the saved stay and requires verified first name, last name and arrival in `current_state`. If only documentary identity is available, staff selects the stay first. Changes to dates, occupancy, room or rate need native re-rating; a separate quote does not establish amendment availability.
