# Amend reply drafts

Proposed wording, not staff-verbatim audit. Guest drafts omit pane Go instructions; staff proposal may say “Review changes, then Go.” No automatic send.

## Clarification

“Could you please confirm which reservation/guest should be amended and [specific changed detail]? We found [verified distinguishing candidate details, if useful].” Do not expose unrelated bookings.

## Before Save

“We have received your request to change [specific fields] for [guest/stay]. [Verified availability/price information, if relevant]. We will confirm the revised booking details once the amendment is completed.” Never say updated before Save.

## After Save + fresh readback

“Your reservation [actual reference] for [guest] has been updated: [verified changed dates/room/occupancy/rate]. [Verified updated price/meal/billing detail if applicable].” Revised attachment only if actual artifact returned. “All other details unchanged” only when readback supports claim.

## Unavailable / partial / uncertain

“The requested [specific change] is not available for [dates]. [Verified alternative, if any].” Generic quote missing combination not sufficient for this claim on held booking.

“We are verifying the amendment outcome for [affected item] and will confirm the revised details once checked.” Already-verified items separate; don't claim entire group done.

Unsupported special preference: acknowledge exact request for staff review; don't promise fulfillment or call harmless preference non-actionable.
