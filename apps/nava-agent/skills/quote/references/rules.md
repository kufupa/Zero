# Quote criteria and prices

- **Dates:** Use explicit dates first. Resolve a yearless date range from dated quoted thread messages or the requested stay when those supply the year; otherwise use the selected message's received date and the stated stay chronology, using the next plausible stay for a future request and carrying year rollover through the range. If still ambiguous, ask. Checkout is departure; preserve each requested segment rather than expanding it or adding a night. For an explicitly one-day event, keep the same date at both ends of the group without inventing a stay.
- **Room lines:** Keep each distinct quantity, accommodation preference, occupancy and scenario on its own `groups[].rooms[]` row. Put the source descriptor in editable `room_type` (requested room type, not a native code). Use the exact stated room quantity, including counts tied to room labels in prose or a table. If a stated guest count expressly requires single occupancy for each, set room `quantity` to that count. Otherwise use editable `quantity: 1` as a labeled default when occupancy is stated but no room count is given — do not `needs_info` or `staff_review` for the missing count alone. Do not infer quantities from headcount alone, room-nights, old replies or native options.
- **Occupancy:** Keep stated adults, children and ages per room. “Accommodation for one official,” or accommodation for one named adult with no other travellers mentioned, means one adult in one room. Read forwards and RFQ attachments too. If one room is requested for a party, that party count is per-room. When the stated number of adult travellers equals the number of requested occupied rooms, use one adult per room. Otherwise require stated allocations or explicit single occupancy for multiple rooms. Default to `children: 0` and `child_ages: []` when no children are mentioned; ask for unclear counts or ages. A room category alone does not establish occupancy.
- **Board:** Put the requested preference in each applicable group or room. Use `BB` for B&B / bed and breakfast and for the public BAR default; use `DBB` only for the combined "dinner bed and breakfast" plan; `BLD` for full board and `RO` for room only. **"Bed and breakfast" plus a priced/optional dinner is `BB`** — carry dinner as a separate extra with its requested scope and a null price unless the hotel has supplied one. Board text does not establish inclusion or a native rate code.
- **Parties and extras:** Keep the requester or booking entity in `party_name`, separate from guest or beneficiary. Search relevant agency or organization for negotiated rates when named; **org match is optional for a public BAR quote** — never block `hms_quote` or escalate to `staff_review` solely because the organization was not found. Verified native eligibility is separate from a name or domain match. Keep public rates separate from negotiated options. Put each requested extra in editable `details.extras[]` as `{description, quantity, price}`, including its stated unit and nulls for unknown amounts. An included meal is not an extra.
- **Property:** If mail explicitly names a different hotel or the hotel is ambiguous, keep the property field unresolved and put the relevant mail evidence on that field. When the mail is silent, staff Prepare uses the selected mailbox property.
- **Native inputs:** Use property, stay dates, quantity and occupancy per room, with stable IDs. Keep event-only groups out of HMS. Search named agencies/companies via `hms_search_parties` and publish the matching `agency_name` or `organization_name`. Omit sales strategy and rate codes for the default. When the guest asks for any available room, omit room codes, beds and features rather than listing the catalogue. Otherwise use only exact catalogue codes that represent a stated constraint, and single, twin, double, queen or king for bed preferences. Breakfast is board, not a room feature. Use nightly summary. Keep staff overrides distinct from HMS prices.
- **Native outputs:** Keep room/rate meaning, dated price, currency, basis, inventory and restrictions distinct. Show an official total only when HMS supplies it. If summing nightly prices, label the sum nonofficial.
