# Create

Read [common rules](../references/common.md), [proposal bindings](../references/tools-and-proposal.md), [field rules](references/rules.md) and [reply drafts](references/replies.md).

1. “Kindly reserve”, “book” or “confirm the rooms” after a quote is Create: carry forward the accepted terms and keep side questions secondary. An agency order asking staff to make a stay is Create even if formatted as a voucher. Distinguish existing-stay submissions (Filing) and VCC settlement notices (Triage). Extract each requested guest, room and stay from the current order. Inspect supplied evidence when the request relies on it. Keep a shared value on every room it covers and an override only on its own room.
2. Publish **one grouped Create action** for a supported multi-room order: one `bookings[]` entry per requested room, in source order, with its assigned guest, dates and occupancy. Preserve every named guest and each explicit room, including separate guest/stay associations; flag unclear assignments instead of inventing them. List all booking IDs in the one `create` action with `details: {}`. The pane derives the room count from those entries. Larger orders outside the pane's booking limit go to staff review; keep their scope intact.
3. Put booking facts in `booking.fields`. Require both `first_name` and `last_name` under `/bookings/i/fields/{first_name,last_name}` for each room, with numeric index `i` in actual pointers. A combined `guest_name` alone does not satisfy Create. Respect evidenced surname-first order and keep initials as supplied. Prefill dates and occupancy, `room_type` and `rate_plan` as HMS catalogue codes, `board`, `organization_name`/`agency_name` from `hms_search_parties`, and `billing_reference` (PO, order or voucher number only). Add editable specs for essential and source-backed fields; leave unused optional controls to the editor. Keep an identifiable booking `propose` when catalogue, party or profile lookup is unavailable and the unresolved native choices can be filled by staff. Anchor yearless dates to the selected email receipt or the relevant requested stay in the thread. When checkout is unclear, use `needs_info` with the known arrival and other supplied fields intact; ask only for the gap. Tool coverage alone is not missing request information.
4. Staff confirms and prepares the booking. After verified Create readback, if the original selected message also supplied a genuine voucher or POP for that new stay, publish a separate Filing draft using that exact file and the readback target. Do not publish a pending filing target.
