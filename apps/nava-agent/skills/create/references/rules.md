# Create fields

In 50 chronological, response-conditioned booking-request journeys, source-cited fields included: guest 43/50, arrival 44/50, departure 43/50, room quantity 20/50, room type 21/50, board 35/50, rate 11/50, contact 27/50, company 24/50 and payment/voucher instructions 15/50. Counts overlap and describe requests, not saved HMS values.

- **Stay/guest:** prefill the requested guest and dates for each stay. Do not distribute guests, dates or rooms across other stays without source support. Arrival → departure → adults are first in the evidenced native entry sequence.
- **Rooms/occupancy:** preserve the requested room category, bed preference and quantity, and match them to a returned HMS option rather than guessing a room code. Do not infer rooms from headcount or occupancy from a per-person price. Standard appeared in 15/50 requests. If no type is specified, select the verified HRCEN Standard Queen native option as an editable default; without a native code, leave it empty and retain the preference. An explicitly stated age 17 is a child: preserve `child_count` and `child_ages`.
- **Board/rate:** preserve requested board and any stated or agreed rate, price, limit and basis. When no rate is stated or agreed, use editable `BAR` as the HRCEN rate plan default; HMS supplies price and inclusions. Do not set a numeric price override. Breakfast was requested in 28/50, dinner and breakfast in 3/50. Company alone does not establish eligibility.
- **Booking source/parties/billing:** source, track, agency, organization, A/R account, payer and billing reference are distinct. Prefill explicitly assigned roles and verified native mappings; an invoice recipient is not necessarily the guest's organization. HRCEN guarantee `NGI` and track `BAR` are editable defaults when unspecified; no corpus-backed deposit or payer default was found.
- **Notes and contact:** bind the guest, booker and special requests to the right stay. Preserve unsupported meal or billing details for staff; a note does not by itself fulfil them.
- **CMS:** default Send on with editable requester recipient and message ID; Labtest Send off. The later letter reached the requester in 217/222 sampled confirmed creates; this is not a checkbox-rate measurement.

Publish `propose` with unknown native choices editable; staff runs Prepare and Go. HMS determines availability/price. Only readback establishes a saved booking; after uncertain Save, re-read before retry.
