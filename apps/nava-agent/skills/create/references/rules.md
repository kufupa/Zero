# Create fields

In 50 chronological, response-conditioned booking-request journeys, source-cited fields included: guest 43/50, arrival 44/50, departure 43/50, room quantity 20/50, room type 21/50, board 35/50, rate 11/50, contact 27/50, company 24/50 and payment/voucher instructions 15/50. Counts overlap and describe requests, not saved HMS values.

- **Stay/guest:** prefill the requested guest and dates for each stay. Stated Check in/out (or In/Out / Date in/out / "night of D Month") must land on every stay's `booking.fields.arrival_date`/`departure_date` as ISO dates — never leave those null on a create propose when the mail states them, and never park them only on a quote group. Do not distribute guests, dates or rooms across other stays without source support. Arrival → departure → adults are first in the evidenced native entry sequence.
- **Rooms/occupancy:** preserve the requested room category, bed preference and quantity, and match them to a returned HMS catalogue code via meaning text (not free-form invention). HRCEN word→code map when the email names a bed/grade: twin→`STWN`, queen→`STQN`, king→`SKNG`, deluxe twin→`DLXTWN`, deluxe queen→`DLXQN`, deluxe king→`DLXKNG`, executive king→`EXKNG`, luxury king→`LUXKNG`, suite→`SUITE`, double / double room (no bed named)→`STWN`. "Single occupancy" / "single occupancy room" / "for one person" means `adults:1` only — never map those phrases to room_type `STQN`. "Standard" alone is not a bed type. When the email is silent on bed/grade, or says only "standard room"/"room(s)"/"single occupancy", use editable `STQN`. Never leave `room_type` null on create — always publish a catalogue code. Do not infer rooms from headcount or occupancy from a per-person price. An explicitly stated age 17 is a child: preserve `child_count` and `child_ages`.
- **Board/rate/guarantee/track:** preserve requested board and any stated or agreed rate. HRCEN silent defaults (56 pre-arrival): guarantee `DEPREQ` (not `NGI`); agency-bound → `GTDAGT` + agency A/R; government org → `NGOVDB` + `GOV` + DBB; corporate → `NCOR1B`/`NCOR2B` + `COR`. Use editable `BAR` only when no rate/board. Do not set a numeric price override.
- **Booking source/parties/billing:** Source, track, agency, organization, A/R account, payer and billing reference are distinct. HRCEN E-Mail source is `EMA`. Whenever the email names a company/travel brand or the sender domain is a company/agency, search `hms_search_parties` for **both** org and agency (`field: name`) before `propose`. Start with the sourced literal; on 0 hits retry the most distinctive token (drop Pty/Ltd/Travel/(PTY) etc.) and the sender-domain stem. On a chosen candidate, bind id from `nativeId` and copy `displayName` exactly into `organization_name`/`agency_name`. Leave ambiguous IDs editable. Keep agency and organization distinct. Do not skip either search because a rate/board was already chosen, and do not put an agency email in `guest_email`.
- **Notes and contact:** always publish a billing `note` (billing instructions only — not guest specials or prior stay chatter). Add `Dinner Gov inclusive of R210.00 + 2 s/drink` only when the organization is government and the rate is `NGOVDB`; never for a corporate/private DBB. Bind guest/booker/special requests to the right stay.
- **CMS:** default Send on with editable requester recipient and message ID; Labtest Send off. The later letter reached the requester in 217/222 sampled confirmed creates; this is not a checkbox-rate measurement.

Publish `propose` with unknown native choices editable; staff runs Prepare and Go. HMS determines availability/price. Only readback establishes a saved booking; after uncertain Save, re-read before retry.
