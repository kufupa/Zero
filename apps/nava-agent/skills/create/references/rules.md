# Create fields

In 50 chronological, response-conditioned booking-request journeys, source-cited fields included: guest 43/50, arrival 44/50, departure 43/50, room quantity 20/50, room type 21/50, board 35/50, rate 11/50, contact 27/50, company 24/50 and payment/voucher instructions 15/50. Counts overlap and describe requests, not saved HMS values.

- **Stay/guest:** prefill the requested guest and dates for each stay. Do not distribute guests, dates or rooms across other stays without source support. Arrival → departure → adults are first in the evidenced native entry sequence.
- **Rooms/occupancy:** preserve the requested room category, bed preference and quantity, and match them to a returned HMS catalogue code via meaning text (not free-form invention). HRCEN word→code map when the email names a bed/grade: twin→`STWN`, queen→`STQN`, king→`SKNG`, deluxe twin→`DLXTWN`, deluxe queen→`DLXQN`, deluxe king→`DLXKNG`, executive king→`EXKNG`, luxury king→`LUXKNG`, suite→`SUITE`, single (no bed named)→`STQN`, double (no bed named)→`STWN`. "Standard" alone is not a bed type. When the email is silent on bed/grade, use `defaults.room_type` from the matched org/agency `hms_search_parties` result (anchors before as_of); only if that is absent fall back to editable `STQN`. Do not infer rooms from headcount or occupancy from a per-person price. An explicitly stated age 17 is a child: preserve `child_count` and `child_ages`.
- **Board/rate:** preserve requested board and any stated or agreed rate, price, limit and basis. Match an explicit rate or board phrase to returned native plan meanings as an editable choice; use editable `BAR` only when neither is stated or agreed. HMS supplies price and inclusions. Do not set a numeric price override. Breakfast was requested in 28/50, dinner and breakfast in 3/50. Company alone does not establish eligibility.
- **Booking source/parties/billing:** Source, track, agency, organization, A/R account, payer and billing reference are distinct. HRCEN’s native E-Mail source is `EMA`; use it as an editable default for email bookings. Search for named source-backed organizations and agencies even when the rate does not require them; bind a single HMS match in the appropriate role. Leave ambiguous or unmatched IDs editable. A company name alone does not establish rate eligibility or payer.
- **Notes and contact:** bind the guest, booker and special requests to the right stay. Preserve unsupported meal or billing details for staff; a note does not by itself fulfil them.
- **CMS:** default Send on with editable requester recipient and message ID; Labtest Send off. The later letter reached the requester in 217/222 sampled confirmed creates; this is not a checkbox-rate measurement.

Publish `propose` with unknown native choices editable; staff runs Prepare and Go. HMS determines availability/price. Only readback establishes a saved booking; after uncertain Save, re-read before retry.
