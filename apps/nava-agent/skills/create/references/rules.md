# Create fields

In 50 chronological, response-conditioned booking-request journeys, source-cited fields included: guest 43/50, arrival 44/50, departure 43/50, room quantity 20/50, room type 21/50, board 35/50, rate 11/50, contact 27/50, company 24/50 and payment/voucher instructions 15/50. Counts overlap and describe requests, not saved HMS values.

- **Stay/guest:** prefill the requested guest and dates for each stay. Stated Check in/out (or In/Out / Date in/out / "night of D Month") must land on every stay's `booking.fields.arrival_date`/`departure_date` as ISO dates — never leave those null on a create propose when the mail states them, and never park them only on a quote group. Do not distribute guests, dates or rooms across other stays without source support. Arrival → departure → adults are first in the evidenced native entry sequence.
- **Rooms/occupancy:** preserve the requested room category, bed preference and quantity, and match them to a returned HMS catalogue code via meaning text (not free-form invention). HRCEN word→code map when the email names a bed/grade: twin→`STWN`, queen→`STQN`, king→`SKNG`, deluxe twin→`DLXTWN`, deluxe queen→`DLXQN`, deluxe king→`DLXKNG`, executive king→`EXKNG`, luxury king→`LUXKNG`, suite→`SUITE`, double / double room (no bed named)→`STWN`. "Single occupancy" / "single occupancy room" / "for one person" means `adults:1` only — never map those phrases to room_type `STQN`. A lone word "single" with no bed/grade still does not override a party `defaults.room_type`. "Standard" alone is not a bed type. When the email is silent on bed/grade, or says only "standard room"/"room(s)"/"single occupancy", bind org/agency first then **must** use `defaults.room_type` from the matched `hms_search_parties` result (agency preferred over org when both return a default); only if that default is absent fall back to editable `STQN`. Never leave `room_type` null on create — always publish a catalogue code. Do not infer rooms from headcount or occupancy from a per-person price. An explicitly stated age 17 is a child: preserve `child_count` and `child_ages`.
- **Board/rate/guarantee/track:** preserve requested board and any stated or agreed rate. HRCEN silent defaults (56 pre-arrival): guarantee `DEPREQ` (not `NGI`); agency-bound → `GTDAGT` + agency A/R; government org → `NGOVDB` + track `GOV` + DBB; corporate → `NCOR1B`/`NCOR2B` + track `COR`. Set `NGOVDB` + `GOV` only when government/gov is paired with DBB / dinner-bed-breakfast (or a "…DBB" confirm), or a named public body (Municipal / Infrastructure System Agent / MISA / Department / Authority) is booked with DBB — bind that org too. A question "what is your government rate for bed and breakfast" alone is not `NGOVDB` (that is breakfast/`NGOVB` territory — leave rate editable for staff). Treat as corporate when corporate/negotiated rate is stated or a commercial company is bound — use party `defaults.rate_plan`/`track` when present, else catalogue `NCOR1B`/`NCOR2B` + `COR`. Prefer party `defaults` from stays before as_of. Use editable `BAR` only when no rate/board and no gov-DBB/corp cue and no org default. Do not set a numeric price override.
- **Booking source/parties/billing:** Source, track, agency, organization, A/R account, payer and billing reference are distinct. HRCEN E-Mail source is `EMA`. Search named organizations and agencies; bind a single HMS match per role. Leave ambiguous IDs editable. When the subject/body labels a party (`Company:` / `Organisation:` / `Organization:` / `Agency:` / `Travel agency:` / `Travel Agent:`), call `hms_search_parties` for that exact sourced string (and a stated acronym) with the matching `kind` before `propose`. Bind the single returned `name`+id into `organization_name`/`organization_id` or `agency_name`/`agency_id`. When the From display/signature is a travel agency (name contains Travel / Travel Consultant, or brand in a `*.travel` / `*travel*.co.za` From domain — e.g. Destini, 360 Degrees Travel), also search `kind: agency` on that brand and bind a single match to `agency_name`/`agency_id` even if a separate `Company:` guest employer was already bound as organization. Do not skip either search because a rate/board was already chosen, and do not put an agency email in `guest_email`.
- **Notes and contact:** always publish a billing `note` (billing instructions only — not guest specials or prior stay chatter). Add `Dinner Gov inclusive of R210.00 + 2 s/drink` only when the organization is government and the rate is `NGOVDB`; never for a corporate/private DBB. Prefer party `defaults.billing_note` when it is a billing-instruction fragment. Bind guest/booker/special requests to the right stay.
- **CMS:** default Send on with editable requester recipient and message ID; Labtest Send off. The later letter reached the requester in 217/222 sampled confirmed creates; this is not a checkbox-rate measurement.

Publish `propose` with unknown native choices editable; staff runs Prepare and Go. HMS determines availability/price. Only readback establishes a saved booking; after uncertain Save, re-read before retry.
