# Create fields

- **Stay and name:** Put ISO `arrival_date` and `departure_date` on each applicable booking. For a yearless range, use the relevant dated thread context or the selected message receipt and plausible stay chronology, including year rollover. Preserve the established arrival if the checkout is ambiguous; set only the unknown date to null. Preserve source spelling and every explicit initial in `first_name`. Use labeled given/surname fields or clear list format to map name parts; do not reverse unlabeled names based on a title alone. Preserve ambiguous full name text for staff. Bind `guest_profile_id` only from a matching native profile. Use `guest_email` for the guest, not the agency; keep booker name/contact separate.
- **Occupancy and room:** Preserve per-room adults, children and ages. When adults are unstated, use a labeled default of the assigned adults if known, otherwise one per room. No children mentioned means editable zero; children mentioned without a count or ages stay unresolved. Headcount or per-person price does not establish room quantity. Put the HMS room code in `room_type`: read `hms_read_catalogue` and pick the code whose meaning matches the requested category and bed (standard queen `STQN`, standard twin `STWN`); keep the requested label only when no code fits. A standard room does not imply a bed type. An explicit single room is a room type; single occupancy alone sets adults. For a silent category, use a verified agency, organization or configured property default in that order.
- **Meals and rate:** Record explicit board in editable `booking.fields.board`: bed and breakfast `BB`, dinner bed and breakfast `DBB`, room only `RO`; preserve any other stated plan as source text. This is draft intent, not a native inclusion claim. Put the HMS rate code in `rate_plan`, matching rate term and board from `hms_read_catalogue` (government DBB `NGOVDB`, government BB `NGOVB`, complimentary BB `CMPBB`); keep the requested words only when no code fits. Keep quoted amounts/basis or limits in staff context. Match the native rate and meal choice where supported; do not replace an explicit rate or board request with BAR or invent an override. When silent, use verified party or configured property defaults; public BAR is an editable default only absent a conflicting preference.
- **Parties and billing:** Organization is the guest's employer or paying company. Agency is the booking intermediary (Travel With Flair, FCM, Tourvest, CWT). An agency's invoice address does not make it the organization. Search both when evidenced, including the booker's agency in the signature, body, voucher or From display name even when a separate employer is present. Always pass that sourced name or acronym as `query` to `hms_search_parties`, plus the correct kind and sender host if known. The domain map is a shortcut; a domain miss is never the end of the search. If an earlier domain-only lookup missed, search the name before leaving any party field blank. Check candidates against the email, especially after a partial search. Copy the returned native name verbatim when it identifies the evidenced party (even if spelling or legal suffix differs); leave null when no returned name fits. Use the tool's selected ID only; several IDs for the same returned name can support the name alone. Employer does not establish rate or credit eligibility. Use `billing_reference` only for PO, order, voucher or account numbers (max 50 characters). Put addresses, VAT numbers and payment directions in the billing note.
- **Native choices:** Keep source, track, guarantee, agency, organization and A/R account separate. Prefer supported party defaults for silent choices and the verified agency A/R when applicable. Use the property configuration for email source and guarantee defaults. Do not assume a named party grants a rate or credit.
- **CMS:** Default `cms_send` on, off for Labtest. Prefill editable `cms_recipient` with the known requester; use the editor's HMS `cms_message_id` default, never the email message ID.
