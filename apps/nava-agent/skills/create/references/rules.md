# Create fields

- **Stay and name:** Extract names from the rooming list row by row, using its headers or surname/given-name separators. For an unlabelled given-name-first entry, use the given name or initials and surname as written; do not expand initials or reverse a name based on a title alone. Use the matching earlier request, accepted quote or rooming list for check-in and check-out when the selected email only confirms or supplies names. Apply shared dates to each applicable room. Read numeric day/month dates in local order. Write ISO `arrival_date` and `departure_date`; resolve yearless dates against the relevant dated thread context or selected receipt, including year rollover. Keep either date if the other is unknown. Bind `guest_profile_id` only from a matching native profile; keep both name fields even without a profile. Use `guest_email` for the guest and keep booker name and contact separate.
- **Occupancy and room:** Preserve per-room adults, children and ages. When adults are unstated, use a labeled default of the assigned adults if known, otherwise one per room. No children mentioned means editable zero; children mentioned without a count or ages stay unresolved. Headcount or per-person price does not establish room quantity. Put the HMS room code in `room_type`: read `hms_read_catalogue` and pick the code whose meaning matches the requested category and bed (standard queen `STQN`, standard twin `STWN`); keep the requested label only when no code fits. A standard room does not imply a bed type. An explicit single room is a room type; single occupancy alone sets adults. For a silent category, use a verified agency, organization or configured property default in that order.
- **Meals and rate:** Record explicit board in editable `booking.fields.board`: bed and breakfast `BB`, dinner bed and breakfast `DBB`, room only `RO`; preserve any other stated plan as source text. This is draft intent, not a native inclusion claim. Put the HMS rate code in `rate_plan`, matching rate term and board from `hms_read_catalogue` (government DBB `NGOVDB`, government BB `NGOVB`, complimentary BB `CMPBB`); keep the requested words only when no code fits. Keep quoted amounts/basis or limits in staff context. Match the native rate and meal choice where supported; do not replace an explicit rate or board request with BAR or invent an override. When silent, use verified party or configured property defaults; public BAR is an editable default only absent a conflicting preference.
- **Parties:** Organization is the guest's employer or paying company. Agency is the booking intermediary. An agency's invoice address alone does not make it the organization. Search each evidenced role with its sourced name or acronym as `query` and its correct kind in `hms_search_parties`. Use the sender host if known and search by name after a domain miss. Compare returned candidates with the employer/payer and intermediary identified in this booking's evidence. A candidate with the same evidenced name or acronym supports the name even when the tool returns no selected ID. Copy the matching native name verbatim into `organization_name` or `agency_name` on every applicable booking; use the tool-selected ID only. If returned names are ambiguous or unrelated, leave the field empty and note the requested name for staff.
- **Billing reference:** Copy the sender's PO, order, client reference, voucher or billing account identifier into `billing_reference` as text, including leading zeros and punctuation, on every booking it covers. Prefer a designated billing reference or PO when both it and a trip reference are given. Look in the current order, referenced earlier messages and voucher text. Keep labels, VAT numbers, addresses and payment directions out of the reference. Maximum 50 characters.
- **Native choices:** Keep source, track, guarantee, parties and A/R separate. Use an HMS guarantee code only for an explicitly requested guarantee that matches the property's catalogue. Keep clear payment instructions in `warnings` for staff even when no guarantee code is established. Leave `guarantee_type` null when silent; neither the party role nor A/R establishes a guarantee. Use the verified A/R when applicable and do not infer rate or credit eligibility from a name.
- **CMS:** Default `cms_send` on, off for Labtest. Prefill editable `cms_recipient` with the known requester; use the editor's HMS `cms_message_id` default, never the email message ID.
