# Create fields

- **Stay and name:** Put ISO `arrival_date` and `departure_date` on each applicable booking. For a yearless range, use the relevant dated thread context or the selected message receipt and plausible stay chronology, including year rollover. Preserve the established arrival if the checkout is ambiguous; set only the unknown date to null. Preserve source spelling and every explicit initial in `first_name`. Use labeled given/surname fields or clear list format to map name parts; do not reverse unlabeled names based on a title alone. Preserve ambiguous full name text for staff. Bind `guest_profile_id` only from a matching native profile. Use `guest_email` for the guest, not the agency; keep booker name/contact separate.
- **Occupancy and room:** Preserve per-room adults, children and ages. When adults are unstated, use a labeled default of the assigned adults if known, otherwise one per room. No children mentioned means editable zero; children mentioned without a count or ages stay unresolved. Headcount or per-person price does not establish room quantity. Keep an explicit category in editable `room_type`, using a uniquely matching HMS catalogue code when available and otherwise the requested label. A standard room does not imply a bed type. An explicit single room is a room type; single occupancy alone sets adults. For a silent category, use a verified agency, organization or configured property default in that order.
- **Meals and rate:** Record explicit board in editable `booking.fields.board`: bed and breakfast `BB`, dinner bed and breakfast `DBB`, room only `RO`; preserve any other stated plan as source text. This is draft intent, not a native inclusion claim. Keep explicit rate terms in editable `rate_plan` (including `COMP` and corporate or government terms). Use a uniquely matching native code if verified; otherwise preserve the requested value for staff and leave native resolution open. Keep quoted amounts/basis or limits in staff context. Match the native rate and meal choice where supported; do not replace an explicit rate or board request with BAR or invent an override. When silent, use verified party or configured property defaults; public BAR is an editable default only absent a conflicting preference.
- **Parties and billing:** Use `hms_search_parties` for each named organization and agency, using the sourced name or acronym, correct kind, and sender host when available. Search an identified booking agency even when a separate employer is present. Bind only a unique native ID; retain each entity's sourced name in its own role. Employer does not establish payer or eligibility. Put explicit bill-to name/reference, PO, order or invoice reference in editable `billing_reference` on the rooms it covers: retain the complete concise reference or supplied invoice-to block, including billing address and tax/account identifiers when part of it. Keep separate payment directions and payment credentials out of the reference. Use a billing `note` for separate routing instructions, not as the only home for the reference.
- **Native choices:** Keep source, track, guarantee, agency, organization and A/R account separate. Prefer supported party defaults for silent choices and the verified agency A/R when applicable. Use the property configuration for email source and guarantee defaults. Do not assume a named party grants a rate or credit.
- **CMS:** Default `cms_send` on, off for Labtest. Prefill editable `cms_recipient` with the known requester; use the editor's HMS `cms_message_id` default, never the email message ID.
