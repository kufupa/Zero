# Create fields

- **Stay and name:** Put ISO `arrival_date` and `departure_date` on each applicable booking. For a yearless range, **anchor the year from dated quoted thread messages or the requested stay itself**, not from an unrelated receipt year when those conflict (Labtest / future stays often sit in the quoted thread). Fall back to the selected message receipt and plausible stay chronology, including year rollover. Preserve the established arrival if the checkout is ambiguous; set only the unknown date to null. Preserve source spelling and every explicit initial in `first_name`. Use labeled given/surname fields or clear list format to map name parts; do not reverse unlabeled names based on a title alone. Preserve ambiguous full name text for staff. Bind `guest_profile_id` only from a matching native profile. Use `guest_email` for the guest, not the agency; keep booker name/contact separate.
- **Occupancy and room:** Preserve per-room adults, children and ages. When adults are unstated, use a labeled default of the assigned adults if known, otherwise one per room. No children mentioned means editable zero; children mentioned without a count or ages stay unresolved. Headcount or per-person price does not establish room quantity. Put the HMS room code in `room_type` for an HRCEN catalogue code, exact category+bed (e.g. standard twin → `STWN`), or a class with one catalogue choice (executive → `EXKNG`, luxury → `LUXKNG`, suite → `SUITE`). For a silent room, use the native room code from party history when available. An explicit category or bed preference wins. For bare standard/single without a bed preference, use a compatible history value or the editable `STQN` default. An explicit single room with a category maps to that catalogue bed family; single occupancy alone sets adults.
- **Meals and rate:** Record explicit **room-scoped** board in editable `booking.fields.board`: canonicalize `B&B` / bed and breakfast → `BB`; dinner bed and breakfast / "DBB" as a single plan → `DBB`; room only → `RO`. **"Bed and breakfast" (or B&B) plus a priced or optional dinner is still `BB`** — dinner is an add-on/extra, not DBB. Only the combined meal-plan phrase "dinner bed and breakfast" / explicit DBB sets `DBB`. Explicit `B&B` must set board `BB` (never leave null). Preserve any other or conflicting plan as source text. Never lift dinner/board from a footer or another room. This is draft intent, not a native inclusion claim. Put the HMS rate code in `rate_plan`, matching rate term and board from `hms_read_catalogue` (government DBB `NGOVDB`, government BB `NGOVB`, complimentary BB `CMPBB`; distinguish GDS/comp); keep the requested words/amount in staff note when no code fits. Match the native rate and meal choice where supported; do not replace an explicit rate or board request with BAR or invent an override. When silent, use verified party+board defaults or `[Client Memory Card]` / party memory; public BAR is an editable default only absent a conflicting preference.
- **Parties and billing:** Organization is the guest's employer or paying company. Agency is the booking intermediary (Travel With Flair, FCM, Tourvest, CWT). An intermediary named on the pro forma invoice is the agency; use the guest’s employer or the explicitly named department as organization. Keep a separate legal billing label in the billing note. Search both when evidenced, including the booker's agency in the signature, body, voucher or From display name even when a separate employer is present. For a short follow-up or agency forward, check the preceding request or accepted quote in `context_before` for the end client. Always pass that sourced name or acronym as `query` to `hms_search_parties`, plus the correct kind and sender host if known. Treat a dedicated agency mailbox localpart such as `sita3@nexustravel.co.za` as possible organization/account evidence: search that acronym or expanded name as the organization while still searching the agency separately. For a travel-agency sender, always also search `hms_search_parties(kind: "agency", ...)` with the sender domain (or inner forwarded client domain on Legacy staff forwards). A named party always wins over `sender_history` and the `[Client Memory Card]`. For organization, if the search finds no credible match to the sourced name, keep that wording in a warning or note for staff and leave the organization fields empty. Preserve a verified native organization name with no ID if its duplicate records cannot be resolved. For an unresolved named agency, preserve its sourced name with a blank ID. Use sender history to pick among ambiguous candidates only when the request is silent about that role. The domain map is a shortcut; a domain miss is never the end of the search. If an earlier domain-only lookup missed, search the name before leaving any party field blank. Check candidates against the email, especially after a partial search. When a lookup returns a candidate matching the company named in the email or earlier thread (read `context_before` for account names) or the sender's domain, bind it; do not leave organization blank or refuse to pick. Copy the returned native name verbatim when it identifies the evidenced party (even if the source uses a trading name, billing name or different spelling). Use the tool's selected ID only; several IDs for the same returned name can support the name alone. Employer does not establish rate or credit eligibility. Put numeric/alphanumeric PO, order or agency voucher numbers that contain **at least one digit** (e.g. `1374219`, `PO 450012`, `Ggfs901`, Travelit `1356971`) in `billing_reference` (max 50 characters). Prefer the order/PO token alone when the mail also cites a voucher (`Order 36484`, not `Voucher …; Order 36484`). Never put a company or agency name in `billing_reference`. Put addresses, VAT numbers and payment directions in the billing note.
- **Native choices:** Keep source, track, guarantee, agency, organization and A/R account separate. Prefer supported party defaults for silent choices and the verified agency A/R when applicable. Emit `guarantee_type` as a native code when stated in the email (map "Agency To Pay Supplier" / "Agency To Pay" / "Bill-Back" → `GTDAGT`, "Non-Guaranteed Individual" / `NGI`, deposit → `GTDDEP` / `DEPREQ`, credit card → `GTDCC`) or supplied by `[Client Memory Card]` / party memory. Use the history choice as an editable default when the request is silent. Email-backed choices win for room, rate, board, guarantee, A/R, billing reference and parties. For a memory-sourced value, use default provenance; keep email quotes for claims the email supports. Do not spend inference on `source_of_business` — leave it null/omitted; code sets native `EMA` with default provenance on HRCEN email publish (staff may override). Do not assume a named party grants a rate or credit.
- **CMS:** Default `cms_send` on, off for Labtest. Prefill editable `cms_recipient` with the known requester; use the editor's HMS `cms_message_id` default, never the email message ID.
