# Create reply drafts

Proposed wording, not audited verbatim staff templates. Only verified facts replace placeholders. Draft only; no automatic send.

## Before Save

“Thank you for your booking request for [guest(s)], arriving [arrival] and departing [departure]. Could you please confirm [specific missing/conflicting detail]?”

If booking vs quote unclear: “Would you like us to make the reservation, or are you requesting a quotation?” Do not ask when explicit booking instruction already clear.

Native unavailability: “The requested [room/rate] is not available for [dates]. We can offer [native verified alternative] at [price, currency, price basis], if suitable.” Omit alternative absent native evidence. No automatic substitution.

## After confirmed Save + readback

“Your reservation for [guest] is confirmed: [arrival] to [departure], [room type], [occupancy], [meal plan], [verified rate/currency/basis]. Booking reference: [actual reference]. [Verified billing instruction or documented special-request note, if relevant].”

Multiple items: list each guest/reference/dates/rate separately; shared facts only when actually shared. Attach confirmation only when real artifact returned. CMS sent claim only from actual result.

## Partial/uncertain

“We are checking the reservation outcome for [affected guest/stay]. We will confirm the booking details once verified.” Do not call it booked, failed, cancelled or paid before readback establishes state. Confirm already-verified items separately.

## Skip / review

Already-existing matching booking → read-supported status response, not duplicate create. Unsupported bill-to/rate/guarantee field → staff-review exact issue; no invented refusal policy. Missing evidence → needs info, not permanent decline.
