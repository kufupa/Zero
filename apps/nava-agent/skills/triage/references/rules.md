# Routing details

- Current new text controls the task; an old quote or booking in the thread is context. An acceptance or instruction to book is Create even when an old confirmation is mentioned. A request for a price/rate/availability without book/proceed is Quote (incomplete occupancy is still Quote). Cancel/cancellation/release wording with a confirmation number is Cancel even if polite, forwarded, or asking the fee/refund/policy for that stay. An existing confirmation alone is not Create or Amend. Publish that routed workflow's proposal (not `workflow: "triage"`) when the primary ask is Create/Quote/Amend/Cancel/Filing. Secondary commission/invoice/meal wording does not keep the case on Triage.
- Keep separate asks, guests, stays and documents. In the labelled corpus 590/1,439 decisions had multiple workflow labels; labels are overlapping model classifications, not completion rates.
- An explicit current voucher or proof-of-payment submission is Filing even when an invoice or payment link is also requested. If no selected PDF is visible, keep Filing with `needs_info`, ask staff to select the PDF and leave attachment actions empty. A pro-forma, payment question, promise to pay, or voucher quoted from an older message is not a current submission.
- Skip OTA/channel, automated and spam mail, including Profitroom, Tiket.com, RateTiger, H-Pay `hospitality.cloud` and Booking.com notices. TBO and Travelit remain in scope. Agency/GDS/no-reply wording alone does not mean OTA: 20/20 sampled agency notices were classified model-helpable. Preserve a guest's actionable request in a pre-stay notice (20/107 contained guest text).
- A one-night shortening is Amend; cancel one booked room through Cancel. Split a new quote from any independent release of a prior stay. More than 8 requested rooms requires staff handling while supported individual tasks remain available.
- Invoice terms appeared in 27/50 selected other-request message bodies and payment terms in 25/50; these overlapping lexical screens can include quoted history. Keep a current invoice or payment question alongside its booking task. In the same convenience sample, 26/50 had a linked outbound message; a reply is not proof of completion.
- A prior reply does not prove the current request is completed. In a 30-case audit, one extra reply and one extra action were needed. A tool failure is not a reason to skip.
